# claude/find ── @ を打って人が出てこない

「@で検索しても出てこない」 OWNER 2026-09-03

## リーダーの見立てと、実際

リーダーからは「`netLike(q)` が `@` ごと `*@aya*` を作るのが原因」と渡されました。
**これは今のコードでは起きていません。**`www/sns.js` の `snsFind()` は
`netFindWho()` に渡す前に先頭の `@` を落としています（`2e6bfad`、2026-08-25、
オーナーの同じ苦情に対する修正）。その commit は `b4be1db`＝ビルド #122 の
祖先なので、**オーナーが実機で見ているビルドに入っています。**

実物で確かめました。アプリを起動して検索欄に打ち、サーバーへ出て行った URL を
読んでいます:

```
"@aya" → GET /rest/v1/profile?...&or=(handle.ilike.*aya*,display.ilike.*aya*)
"aya"  → GET /rest/v1/profile?...&or=(handle.ilike.*aya*,display.ilike.*aya*)
```

同じです。半角 `@` は既に落ちています。**`netLike()` は無実で、そこを書き換えると
リーダー自身が 1 で警告した「投稿の検索から `@` が消える」新しいバグを入れるだけ
です。触りません。**

## 本当に赤いところ ── 全角 `＠`

オーナーは日本語キーボードで打ちます。日本語 IME の `＠` は **U+FF20（全角）**で、
`/^@+/` の `@` は U+0040 です。落ちません。

画面を実際に叩いて数えた行数:

| 打った文字 | 出た人 |
|---|---|
| `@aya` (U+0040) | 1 |
| `＠aya` (U+FF20) | **0** |
| `＠` 混じり `@＠aya` | **0** |
| `aya` | 1 |
| `@AYA` | 1 |

`＠aya` は `handle.ilike.*＠aya*` になり、`profile.handle` は
`^[a-z0-9_]{2,24}$`（`supabase/schema.sql`）なので必ず 0 件です。
**8月25日の修正が半角しか見ていなかった、というのが今日の苦情の中身です。**

## 直しの形 ── 足すのではなく、訊いていることを書き換える

`@` を落とす規則は**二箇所に書かれています**。

- `www/net.js` の `netHandleOf()` ── コメントが自分で「One place」と言っている
- `www/sns.js` の `snsFind()` ── その規則をインラインの正規表現でもう一度書いている

CLAUDE.md 「One place, not fifteen」の、コメントが一箇所だと名乗っている横に二つ目が
ある形そのものです。条件を足さず、**訊いていることを書き換えます。**

「先頭が U+0040 か」ではなく「**先頭が、人を指すために打たれた `@` か**」を訊く
一箇所を作り、両方がそれを呼びます。`@` は電話のキーボードで二通りに書けます。

- `netAtOff(s)`（新・`www/net.js`）── 打たれた `@` を先頭からだけ落とす。半角と全角
- `netHandleOf()` は `netAtOff()` を呼ぶ形に。**小文字化と空白潰しは残します** ──
  それは「@ とは何か」ではなく「handle とは何か」の規則で、別の文
- `snsFind()` のインライン正規表現は**消して** `netAtOff()` を呼びます

## リーダーの四つの問いへの答え

1. **どこで落とすか ── 人を探す側だけ。`netLike()` の中ではありません。**
   `netLike()` は人の検索と投稿の検索の両方が使い、投稿の本文の `@` はその人が
   打った文字です。落とす意味があるのは `snsFind()` が「これは人だ」と決めた
   その一点だけ。`netLike()` の `[*,()]` の行には触れません
2. **`display` も同じ扱いでよい。**`ilike` は部分一致なので、先頭の `@` を落としても
   表示名に `@` が入っている人は見つかります。**ただし `netHandleOf()` は使えません**
   ── あれは空白を全部潰すので、`aya tanaka` のような表示名の検索が壊れます。
   だから落とすのは `@` だけの `netAtOff()` を分けます
3. **先頭だけ。**真ん中の `＠` は打たれた文字です。8月25日の判断を変えません
4. **`netLike()` の `[*,()]` は意味を変えません。**触っていません

## リーダーの四つの仮説 ── 一つずつ潰した

偽サーバーを立てて実際に走らせた結果です。

| 仮説 | 結果 |
|---|---|
| `select=...,av` が 400 で落ちて「訊けなかった」になる | **画面は既に分けている。**0 件は "Nothing found"、400 はサーバーの文言。**ただしオーナー側の原因としては生きています**（下） |
| `netLike()` が `_` を落とさない | **本当。**`netLike('a_b')` は `*a_b*` のまま。`ilike` の `_` は任意の一文字 |
| `netLangNames` が失敗すると `ok` も `bad` も呼ばれず永久に待つ | **違う。**`function(){ done({}); }` があり、言語の問いを 400 にしても人は 1 人出る |
| 原因はまだ誰も知らない | **全角 `＠`（U+FF20）でした。**上の表のとおり |

### オーナー側に残っている、もう一つの可能性

`av` は `alter table profile add column if not exists av jsonb`（`supabase/schema.sql`
65 行）で足されています。`docs/STATE.md`「オーナーの側に残っているもの」1 は
**`schema.sql` をまだダッシュボードに流していない**と言っています。流れていなければ
`select=id,handle,display,av` は 400 で、検索は赤い文言を出します。
**実機で「いません」と出ているのか、サーバーの文言が出ているのかを見てもらえば
どちらか分かります。**これは `www/` では直せません。

### 直していないもの ── `_` のワイルドカード

`netLike()` は `_` を素通しするので、`aya_b` を探すと `ayaXb` にも当たります。
**本当の欠陥ですが、今日の苦情の原因ではありません**（当たりが増えるだけで、
0 件にはならない）。`netLike()` は投稿の検索と共有していて、そこでも `_` は
文字そのものであるべきです。CLAUDE.md §Scope の「ついでだから直した」を
避けて**触っていません。別の一件です。**

## 検査 ── `tools/find-check.mjs`（新）

リーダーが `tools/` の新規一本と `package.json` / `tools/gate.mjs` の一行を
許可したので置きました。`SLOW` に入って **34 本 → 35 本**です
（`CLAUDE.md` の「thirty-four checks」は falsify されました。あのファイルは
私の持ち物ではないので**リーダーが直してください**）。

十一の主張を持ちます。偽物は `netSend()` だけなので `netLike()` も
`netFindWho()` も `netLangNames()` も本物が走ります。

見た赤は六つ、全部バグを入れてから:

1. 旧 `/^@+/` を戻す → 全角 `＠aya` が 0 件（オーナーのバグ）
2. `netLike()` で `@` を落とす（リーダー当初案）→ 投稿の検索と真ん中の `@` が壊れる
3. `netHandleOf()` を流用 → `*ayatanaka*` になり表示名の空白が潰れる
4. `display` を問いから外す → 六つ赤
5. `netLangNames` の `bad` を空関数に → 人が出ず待ち続ける
6. `no()` から `bad` を外す → 0 件と訊けなかったが同じ言葉になる
