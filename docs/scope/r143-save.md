## 測ったこと（原因は分かっていない）

本物のコード、偽の線は `netSend()` か Playwright の route だけ。オーナーの順番（描く → 保存 → 別の字を描く → 保存 → もう一つ）を、
画面の押下（ltGo → editLetter → マウスで一本 → 右上の保存）で通した。

| 一度目の答え | 結果 |
|---|---|
| 着いた（本文なし／同じ本文／違う本文＝合わせた） | 三回とも着いて「保存しました」、前の画面へ |
| 一つの slice が 500 | ポップ、画面に残る、次の押下は送られる |
| `said:'kept'` | 着いた扱い（別件 ── 報告に書く） |
| 電波なし | ポップ、次の押下は送られる |
| 401 → 更新 → 着く | 送られる |
| 2 秒遅い線で二度押し | 二度目は列に入り、一度目のあと送られる |

どれでも `KEEP_BUSY` と `NET_SYNCING` は下りた。止まったのは、`keepSave()` の中で `KEEP_BUSY` を上げてから下ろすまでの
間に投げた時だけ（手で入れて測った）。オーナーの電話で何が投げたか、あるいは別の理由かは分かっていない。

## 直したこと

`keepSave()` の門を書き直した。保存は番号の付いた一回で、終わり方は二つ（着いた・着かなかった）。投げたら「着かなかった」で、
端末を戻し、「保存できませんでした (keep <印>)」と言い、上げた物を下ろす。上がったままの門に押下が来て、線の上に何も
無い（`NET_OUT`・`NET_SYNCING`・`NET_NEXT` が空）なら、「保存できませんでした (keep busy)」と言って、その押下を送る。

## net.js で見つけた物（r140 の領分、触っていない）

- `netSlicesUp()` の最後の `langLoad(); render();` が投げると `ok` が呼ばれず `NET_SYNCING` が上がったまま ── 以後の保存は
  全部 `NET_NEXT` に積まれて出ない。今回の直しは「線の上に何かある」と見て黙らない（r140 の星が出る前提）。
- `netPop()` は印に `−` か `≠` があって status 0 だと何も出さない。保存の道でそうなる所は、開いている言語では見つからなかった。
- `netSliceUp()` は `said:'kept'`/`'shrank'` を `done(false)`（着いた・動かず）で返すので、その slice が書かれていなくても
  「保存しました」が出る。
