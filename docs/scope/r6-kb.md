## 測ったこと（headless、起動を4回再現）

古いビルドが残した **id 無しの kb slice**（`lingua.<id>.kb`、`slRd` の disk
fallback）が phone にあり、サーバーにも同じ言語の kb がある状態で起動する。

| | 画面の枚数 `kbBoards()` | サーバーの板 |
|---|---|---|
| 起動1 | 3 | 2 |
| 起動2 | 4 | 3 |
| 起動3 | 5 | 4 |
| 起動4 | 6 | 5 |

サーバーの id は毎回 `k<時刻>_1` が一つ増える。`slWr` はメモリにしか書かない
ので **ディスクの id 無しの写しは永久に id 無しのまま**で、`kbIded` が起動の
たびに**別の乱数 id** を打つ。`syKeyOf` から見て同じ板の写しが毎回別の行に
なり、`syArr` が「両方残す」を働かせる。

## やったこと

前の係（session_01Ppd1wt、archive 済み）が `95bc95bb` で id を中身から決める
半分を入れていた。リーダーの指示（2026-09-07）でこの枝を引き継ぎ、残り半分を
入れた ── **同じ中身の板の写しを一枚にまとめる**（`87a2e2d8`）。

| 起動 | 直す前 | 中身から id | まとめたあと |
|---|---|---|---|
| 画面の枚数 | 3 → 4 → 5 → 6 | 3, 3, 3, 3 | 2, 2, 2, 2 |
| サーバーの板 | 2 → 3 → 4 → 5 | 2, 2, 2, 2 | 1, 1, 1, 1 |

画面の 2 は「無料 QWERTY ＋ 人の板一枚」で、これが正しい数。
