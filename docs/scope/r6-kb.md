# r6-kb ── キーボードが起動ごとに増えるのを止める

- 日付: 2026-09-07
- 枝: `claude/r6-kb`（`master` の `5498f8b0` から）
- オーナー実機 2026-09-07:「アップデートするたびにキーボード増殖してる。
  トリガーわからんけど毎回増えてる」「消していい。そもそも増殖させるな」

## 測ったこと（headless、起動を4回再現）

古いビルドが残した **id 無しの kb slice**（`lingua.<id>.kb`、`slRd` の disk
fallback）が phone にあり、サーバーにも同じ言語の kb がある状態で起動する。

| | 画面の枚数 `kbBoards()` | サーバーの板 |
|---|---|---|
| 起動1 | 3 | 2 |
| 起動2 | 4 | 3 |
| 起動3 | 5 | 4 |
| 起動4 | 6 | 5 |

サーバーの id は毎回 `k<時刻>_1` が一つ増える。`slWr` はメモリにしか書かない
ので **ディスクの id 無しの写しは永久に id 無しのまま**で、`kbIded` が起動の
たびに**別の乱数 id** を打つ。`syKeyOf` から見て同じ板の写しが毎回別の行に
なり、`syArr` が「両方残す」を働かせる。

## 止まっている ── 同じ枝に別セッションが入っている

計測の途中で session_01Ppd1wt が `95bc95bb`（`kbHash`）と `5e9db21a`
（kb-check 四本）をこの枝に push した。`www/keyboard.js` を二人で触ることに
なるので、こちらはコードを書かずに止める。docs/SESSIONS.md 4・6。

その直しを同じ計測にかけた結果（枝には触らず worktree で）:

| | 直す前 | 5e9db21a |
|---|---|---|
| 起動1 | 3 | 3 |
| 起動2 | 4 | 3 |
| 起動3 | 5 | 3 |
| 起動4 | 6 | 3 |

**増えるのは止まる。減りはしない。** 3 枚は「無料 QWERTY ＋ 同じ板の写し
2 枚」で、すでに 8 枚になっている実機は 8 枚のまま。あちらの CHANGELOG は
「まとめることはしません。重複は手で消してください」と書いていて、OWNER の
「消していい。そもそも増殖させるな」と逆を向いている。

## 誰かがまだやること

- `kbBoardsOf` で、**id を除いた中身が完全に同じ写しだけ**を 1 枚にする
  （少しでも違えば残す）。`KB.at` は無料 QWERTY を頭に置いた並びの番号なので、
  写しを落としたら指し直す。
- `docs/CHANGELOG.md` に DELETE REVIEW（何を・条件・OWNER の一言）。
- `again-check` に「起動ごとに kb の枚数が増えない」。

## 触らないもの

それ以外すべて。`www/index.html` は一行も触らない（他のセッションが持って
いる）。`www/sync.js` も触らない ── 直すのは id の決め方であって、合流の
規則ではない。
