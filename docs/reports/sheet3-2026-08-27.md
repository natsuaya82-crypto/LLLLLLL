## 2-1 の原因（確定）

**`<a download>` ではありません。** `www/sheet.js` は既に `backup.js` と同じ道を通って
います — `sharePlug()` → `Capacitor.nativePromise` です。`registerFont` も
`Capacitor.Plugins` も使っていません。

原因は **native 側にその口がない** ことです。

- `www/sheet.js:1089` — `p('LinguaShare', 'sheet', {name:shFileName(), b64:btoa(pdf)})`
- `ios/App/App/LinguaShare.swift:24-35` — `pluginMethods` は
  `write` `registerFont` `keep` `kept` `dropKept` `keepVoice` `voice` `dropVoice`
  `pickPhoto` `audio` `settings` の11個。**`sheet` はありません。**
- `@objc func sheet` もファイル中に存在しません。

Capacitor のブリッジは `pluginMethods` にない名前を **reject** します。なので
`shMake()` は必ず `['catch']` に落ち、`t('wr.nobridge')`
「ファイルの保存先に届いていません。」を出して終わります。**PDF はどこにも書かれません。**

`www/sheet.js:1073` のコメント自身がそう書いてありました ——
「There is no Swift behind `sheet` yet -- LinguaShare.swift has keep/kept/write/
pickPhoto/audio and not this」。書き出しは **一度も動いたことがありません。**

直し方: `LinguaShare.swift` に `sheet` を足す。`keep()` と同じ Documents の下
（`FileManager.documentDirectory`）へ。`assets-check` が Sources ビルドフェーズを
見るので、新しい `.swift` を足すのではなく **既存の `LinguaShare.swift` に生やす**のが
安全です（＝ `project.pbxproj` を触らずに済む）。

## 2-2 の原因（確定）

**自分で出した PDF を自分で読み戻せません。** そしてそれは
「戻す側が壊れている」のではなく、**書き出す側が写真を持っていない** からです。

- `shSheet()`（`www/sheet.js:240` 付近）が PDF に入れる画像は名前の絵だけで、
  `/ColorSpace /DeviceGray /BitsPerComponent 8` の **生ストリーム**です。
  `/DCTDecode` は一つもありません。
- 読む側 `shPdfJpeg()`（`:345`）は `/DCTDecode` を探します → **null**。
- `shPdfWhy()`（`:370`）は `/DCTDecode` なし・`/Subtype /Image` あり → `'packed'`。
- `shTakeFile()`（`:1198`）は `jpg` が null なので `why==='drawn'` でもないため
  `t('wr.pdf.no')`「この PDF の中の絵は取り出せません。」で refuse。

**人には何が見えるか:** 黙ってはいません。`shFail()` が `s.why` に入れ、
`shInHTML()` が `<div class="note">` で出します。ただし出る文は
「この PDF の中の絵は取り出せません」で、**本当の理由（これは紙に印刷して手で書いて
スキャンしたものではない）を言っていません。**

なお本来の道 —— 印刷 → 手で書く → スキャン → その PDF を戻す —— なら
スキャナは `/DCTDecode` を返すので読めます。オーナーが 2-1 で紙を一枚も
手にできていない以上、**戻す側で試せたのは「アプリが出した PDF そのもの」だけ**
だったはずで、それがこの refuse に当たります。
