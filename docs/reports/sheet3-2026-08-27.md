## 2-2 の原因（確定）

**自分で出した PDF を自分で読み戻せません。** そしてそれは
「戻す側が壊れている」のではなく、**書き出す側が写真を持っていない** からです。

- `shSheet()`（`www/sheet.js:240` 付近）が PDF に入れる画像は名前の絵だけで、
  `/ColorSpace /DeviceGray /BitsPerComponent 8` の **生ストリーム**です。
  `/DCTDecode` は一つもありません。
- 読む側 `shPdfJpeg()`（`:345`）は `/DCTDecode` を探します → **null**。
- `shPdfWhy()`（`:370`）は `/DCTDecode` なし・`/Subtype /Image` あり → `'packed'`。
- `shTakeFile()`（`:1198`）は `jpg` が null なので `why==='drawn'` でもないため
  `t('wr.pdf.no')`「この PDF の中の絵は取り出せません。」で refuse。

**人には何が見えるか:** 黙ってはいません。`shFail()` が `s.why` に入れ、
`shInHTML()` が `<div class="note">` で出します。ただし出る文は
「この PDF の中の絵は取り出せません」で、**本当の理由（これは紙に印刷して手で書いて
スキャンしたものではない）を言っていません。**

なお本来の道 —— 印刷 → 手で書く → スキャン → その PDF を戻す —— なら
スキャナは `/DCTDecode` を返すので読めます。オーナーが 2-1 で紙を一枚も
手にできていない以上、**戻す側で試せたのは「アプリが出した PDF そのもの」だけ**
だったはずで、それがこの refuse に当たります。

## 2-1 — 書き出したシートが Documents に落ちる

`ios/App/App/LinguaShare.swift` に `sheet` を足しました。`pluginMethods` に一行、
`sheets()` と `@objc func sheet(_:)`。**新しい `.swift` は作っていません** ので
`project.pbxproj` は触っていません（`npm run assets` 緑、swift 20 files すべて
Sources phase に在り）。

`www/sheet.js` は一行も変えていません。呼び方は最初から正しかったからです
（`Capacitor.nativePromise`。`registerPlugin` も `Capacitor.Plugins` も使って
いません）。

**どう渡すか:** `backup.js` の `keep()` と同じ Documents です。
`Documents/Sheets/<name>.pdf`。`UIFileSharingEnabled` と
`LSSupportsOpeningDocumentsInPlace` は `Info.plist` に既にあるので Files アプリ
から見えます。**二つ目の書き出し方は作っていません。**

**一つだけ `keep()` と違うところ、そしてこれは直しの一部です:**
`shFileName()` は言語 id を持たないので毎回同じ名前になります。素直に書くと、
Files で開いてペンで書いた一枚が次の書き出しで消えます。**上書きせず**
`<name> 2.pdf` `<name> 3.pdf` と続けます。何も消しません。

**決定として上げるもの（実装はしていません）:** 共有シート（`UIActivityView
Controller`）にするか、Documents のままにするか。今は Documents だけで、
これは `backup.js` と同じ道です。押した人が「どこに行ったのか」を知るには
Files を開く必要があります。トーストは `wr.out.ok`「書き出しました」のままで、
どこに行ったかは書いていません（規則：説明文を書かない）。**変えるなら決定です。**

## 2-2 — 戻した PDF

**答え: いいえ、自分の出した PDF は自分で読み戻せません。**

実測（`shSheet(['a','b','c'])`、64,649 バイト）:

```
why: 'packed'   jpeg: false   head: '%PDF-1.4'
→ 「この PDF の中の絵は取り出せません。」で拒否、got: null
```

`shSheet()` が PDF に入れる画像は箱の上の名前だけで、
`/ColorSpace /DeviceGray /BitsPerComponent 8` の**フィルタなし生ストリーム**です。
`/DCTDecode` は一つもありません。

**そして、拒否するのは正しいです。** 白紙のシートには何も書かれておらず、
読めば二十枠すべて空 = `wr.empty.all` になるだけです。本来の道
（印刷 → 手で書く → スキャン → 戻す）ならスキャナが `/DCTDecode` を返すので
読めます。**直すところは「拒否」ではなく「言っている理由」でした。**

**人には何が見えていたか:** 黙ってはいません。`shFail()` → `s.why` →
`shInHTML()` の `<div class="note">`。ただし出ていた文
「この PDF の中の絵は取り出せません。」は**別のファイルについての文**でした。

`shPdfWhy()` の `packed` が「画像があって JPEG ではない」だったためです。
アプリ自身のシートは名前が画像なので `packed` になります。

**直し:** 写真でない画像と、開けない画像を分けるのは**フィルタ**です。スキャナが
作るページは必ずフィルタの後ろにいます（`/DCTDecode`、そうでなければ Flate・
JPX・CCITT）。`shSheet()` が書くのはフィルタなしの 8bit グレーで、スキャナは
それを作りません。`shPdfWhy()` は画像の辞書だけを見てフィルタを問うようになり、
アプリ自身のシートは `drawn` =「この PDF の中に写真がありません。」になります。

`shPdfImageAt()` が足りた関数一つ（`/Subtype /Image` と `/Subtype/Image` の
両方。PDF はどちらも書きます）。**保存されるものは何も変わりません。拒否する
かどうかも変わりません。変わるのは人が読む一文だけです。**

**そのあと入れたもの:** 画面の上でペンで書いた PDF のレンダラ。下 § 3。

# 3. 画面の上で書いた PDF を電話に描かせる

「pdfkitのレンダラやろう」OWNER 2026-08-27。BACKLOG に上げたものが決定に
なったので、そのまま入れました（BACKLOG の項目は消しました ── 直したら規則を
消す、と同じ扱い）。

## 何が読めるようになるか

写真の入っていない PDF は二種類あって、どちらも同じ問題です:

- **画面の上でペンで書いたもの** ── iPad の Markup、GoodNotes。インクがページに
  「描かれて」いて、ページの写真の画素ではない
- **ページがこのファイルのほどけないフィルタの後ろにいるもの**（Flate、JPX、
  CCITT）。PNG を吐くスキャナがこれです

どちらもレンダラが要り、`www/sheet.js` はレンダラではなく、電話は持っています。

## 形

`ios/App/App/LinguaShare.swift` に `renderPdf`。一ページ目を `SH_LOOK`（2200px）の
JPEG にして base64 で返します。**大きさの数はこれまで通り `www/sheet.js` の
一箇所**で、Swift 側は渡された数を使います。

`www/sheet.js` に `shPdfDraw()`。**`shPdfJpeg()` 以外で PDF が絵になる唯一の
場所**で、`shLook()` から先は一文字も変わりません ── 同じ閾値、同じ四隅のマーク、
同じ帯。二本目の道はページが二通りに描かれて静かに食い違う道です。

**描けるかどうかはレンダラが答えることにしました。** `shPdfWhy()` は「どの種類の
ファイルが来たか」を言うもので、それは別の問いです。誰に試させるかをそれに
決めさせると、本当に知っているものの前に推測を置くことになります。なので
**JPEG が取れなかったものは全部渡します** ── PDF ですらないファイルも。
CoreGraphics がそれを断り、それが答えです。

電話がないとき（ブラウザ、このビルドより前のアプリ）は聞く相手がいないので、
**これまでの文がそのまま出ます。** 退行はありません。

## PDFKit ではなく CoreGraphics、これは好みではありません

`LinguaShare.swift` 自身が記録しています ── `import WidgetKit` をここに書いたら
`PHPickerViewController` がスコープから消えて **#84 が落ちました**（a82a633 から
緑だったピッカーで）。`CGPDFDocument` と `drawPDFPage` は UIKit のもので、
**このファイルの上にある import だけで足ります。** 新しい `.swift` も作って
いないので `project.pbxproj` は無傷です（`npm run assets` 緑、swift 20 files）。

`getDrawingTransform` を使うのは、**ページが回転を持つことがある**からです
（スキャナの PDF はよく持ちます）。九十度回った紙は四隅のマークが違う隅にあり、
**失敗せずに「シートでないもの」として読まれます。**

**一ページ目だけ**です。これは読む側がずっとそうしてきたことで
（`shPdfJpeg()` は一番大きい JPEG を一つ返し、`shPage()` は一ページ読む）、
二十一個目の名前は二枚目のシートであって、このシートの二ページ目ではありません。

## 新しく保存されるものはありません

送った PDF も返ってきた絵もどこにも書かれず、読み終わったら消えます。

## 検査 ── `tools/sheet-check.mjs` § 8

Swift は Linux で走りません。`backup-check` が `keep()` に引くのと同じ線で、

# 4. 描くのは PDFKit ── `drawPDFPage` は注釈を描かない

「俺たちがアプリで作ったpdfで書いた文字が読み込めればなに使ってもいいのよ」
OWNER 2026-08-27。

**§3 で入れたものにバグがありました。自分で見つけて直しました。**

`CGContext.drawPDFPage` はページの**内容ストリーム**を描きます。**注釈を
描きません。** iOS の Markup ── Files、Mail、Quick Look で PDF に指や
Apple Pencil で書くやつ ── は**一本一本を PDF の注釈として保存**します。
ページの横に、自分の appearance stream を持ったオブジェクトとして。

つまり §3 のままなら、ペンで書いたシートは**印刷されたときの白紙のまま**
出てきます。そして **何も throw しません**:

- 四隅のマークは見つかる
- 帯は読める
- 二十の名前は返ってくる
- **どの枠も空**

人の書いたものだけが抜けた、正しく見える答え。このアプリが一番拒みたい形です。

GoodNotes のように**書き出しのときに線をページに焼き込む**アプリなら
`drawPDFPage` でも出ます。**半分だけ動く**のが一番たちが悪いところでした。

## 直し
