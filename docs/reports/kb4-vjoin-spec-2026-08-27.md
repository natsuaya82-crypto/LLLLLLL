# 縦結合（a1+a2）の仕様 ── リーダーへの確認、実装前

「横で。縦はリーダーに確認して許可降りたらやって欲しい」OWNER 2026-08-27

横の結合は `claude/kb4` に入っている。縦はまだ書いていない。**これは仕様であって
実装ではない**。許可が要るのは私の担当外のファイルが二つ要るからで、私の判断で
待っているのではない。

---

## 1. いま何がそうなっているか

保存形は `layer.rows = [[Key]]` で、`Key` は `{w, k, v, f}`。**`w` は幅しかない。**
「このキーは二行ぶんの高さがある」と言う場所がどこにもない。

描き手も三つあり、三つとも一行ずつ描いている。

| どこ | いま | 誰のもの |
|---|---|---|
| `www/keyboard.js` `kbHTML()` | 行ごとに `<div class="kbrow">` を出す | **私** (kb4) |
| `www/index.html` `.kb.kbsheet .kbrow` | `display:grid` が**行ごとに**ある | `claude/sheet3` ほか |
| `ios/.../KeyBoardView.swift` `layoutSubviews` | `rowH = 高さ/行数`、キーは `free * w/total` | `claude/plan2` |

`grid-row: span 2` は同じグリッドの中でしか効かない。行ごとにグリッドがある
いまの形では、CSS 側で縦にまたぐことは**できない**。keyboard.js だけで閉じない
のはここ。

---

## 2. 保存形 ── 何を足すか

二つ足す。どちらも既存のファイルを壊さない形を選んである。

**(a) 上のキーに `h`。** `k.h = 2` で二行ぶん。無いときは 1。
`Key` は配列ではなくオブジェクトなので `JSON.stringify` が落とさない
（行に付けたプロパティは落ちる ── ルール19 が `al` を蹴った理由と同じ）。

**(b) 下の行に、その真下を埋める `{k:'gap', w:同じ, up:1}`。**

`up` を付けた **gap** にするのが要点で、`{k:'under'}` のような新しい種類には
しない。理由は互換で、これは推測ではなく Swift を読んだ結果:

- `KeyBoardView.swift:52` — `case "gap"` は透明・押せない。
- `KeyBoardView.swift:62` — **`default:` は普通のキーとして灰色に描く**。
- `KeyboardViewController.swift:174` — `default:` は `typed(key.t)` を呼ぶ。

つまり新しい `k` を作ると、**縦結合を知らないビルドの拡張では、灰色の空きキーが
そこに立って、押すと何も入らない**。`gap` なら透明の穴になり、上のキーが一行ぶん
の高さで立つだけになる ── 読めるし、打てるし、字は正しい。`up` は `Decodable` の
知らないキーなので黙って無視される。`h` も同じ（`Key` に `h` は無い。`Board.h` は
別物）。

**古い側で開いても、レイアウトは崩れずに縦結合ぶんだけが無かったことになる。**
これが `k:'under'` を採らない理由。

**ただでついてくるもの、確かめた:**

- `kbUsed()` は幅を足すだけなので、影の gap を数えて行の合計が合う。
- `kbCols()` も同じ。シートの幅は変わらない。
- `kbColHas(at, w, ci)` は種類を見ないので、影の gap も同じ列に居る。
- `kbDelCol()` は重なりぶんキーを細くする。上のキーと影の gap は `at` も `w` も
  同じなので、**同じだけ細くなる**。書き足すものは無い。

## 3. 決まっていないこと ── これはオーナーのもの

**縦に繋がった二行の寄せ（左/中央/右）をどうするか。** 寄せは行ごとの機能で、
`kbLead()` が行の先頭の空きを決める。上の行を中央に寄せて下をそのままにすると、
**影の gap がキーの真下から外れる**。

三つ考えられる:

1. 片方を寄せたらもう片方も同じだけ寄る（縛られた二行は一つとして寄る）
2. 縦結合のある行は寄せボタンを出さない
3. 保存のたびに影の `at` を上のキーから引き直す（＝下の行の他のキーが動く）

`docs/FEATURE_RULES.md`「Deciding」に従って**ここでは決めない**。コードが今
どうなっているかは上のとおり。

## 4. 私が書く側（`www/keyboard.js`、kb-check、i18n）

許可が出たら書くもの:

- `kbTapKey()` ── いまは隣（`i±1`）を押すと横に繋ぐ。**真上・真下**を押したら
  縦に繋ぐ。行が違うので「隣」の判定は `KBH.r===ri±1` かつ **`at` が同じ**、つまり
  同じ列から始まって同じ幅であること。ずれていたら繋がない（何も起きない）。
- `kbVJoin(ri, ki)` ── 上のキーに `h=2`、下の実体を `{k:'gap', up:1}` に置き換える。
  `kbJoin()` の隣。
- 戻す ── 影の gap を空きマスに戻し、`h` を消す。横の解除と同じ扱い。
- `kbCellAdd()` ── 影の gap は空きマスではないので、押しても何も入らない。
- `kbDelRow()` ── **上の行を消したら下の影は空きマスに戻す**。下の行を消したら上の
  `h` を戻す。どちらも「消えたキーの跡が残る」のが一番まずい形。
- `kbRoomIn()` / `kbRoomRow()` ── 変わらない。縦結合は行も幅も増やさない。
- 元に戻す ── レイアウト丸ごとの控えなので、書き足すものは無い。

`tools/kb-check.mjs` に足す主張（赤くしてから信じる、いつもどおり）:

1. 縦に繋いだあと、**下の行の他のキーが左にずれていない**
2. 上の行を消すと、下の影が空きマスに戻る（跡が残らない）
3. 下の行を消すと、上のキーが一行ぶんに戻る
4. 列を切ると、上のキーと影が**同じだけ**細くなる（片方だけ細るのが本命の壊れ方）
5. 一段戻すと、繋ぐ前とバイト単位で同じ
6. 保存して読み直しても `h` と `up` が残っている
7. 縦結合の無いキーボードが、これを入れる前と一字一句同じに書き出される

## 5. 他所に要るもの ── **これは私が触れない**

### `www/index.html`（`claude/sheet3` ほかが持っている）

`.kb.kbsheet .kbrow` の grid を、**シート全体で一つの grid** にする必要がある。

```
.kb.kbsheet{display:grid;grid-template-columns:repeat(var(--kc,20),1fr);
            grid-auto-rows:var(--kh);gap:5px}
```

キーは `grid-column:span n` に加えて `grid-row:span 2` を持つ。いま `.kbrow` に
付いている `--rh` はそのまま使える（`.kbk` の `min-height` が
`calc(var(--kh) * var(--rh))`）。

**巻き添えになるもの、読んだうえで:** `.kb.kbsheet .kbrow.sel::before`（行が選ばれ
ている帯）と `.kbband`（列の帯）は、どちらも行ごとのグリッドを前提に位置を出して
いる。行の `<div>` が無くなると両方書き直しになる。**これは見た目の作り直しであって
私の担当の一行ではない。** `index.html` を持っている session に渡すか、その file が
分割されるまで待つかはリーダーの判断。

### `ios/App/LinguaKeyboard/KeyBoardView.swift`（`claude/plan2` が持っている）

`layoutSubviews`（161行）は行を順に降りていく。要るのは二行:

- 影（`k=="gap"` かつ `up`）は **frame を与えず描かない**が、`x` は幅ぶん進める
- `h==2` のキーは `height: rowH*2 + gap`

行の総幅は影を数えたままで合うので、`total` も `free` も触らない。
`Shared.swift` の `Key` に `let h: Double?` と `let up: Int?` が要る。

**同じアプリの中で app と拡張は一緒に上がるので、ここが遅れて困るのは
バックアップから戻した板とサーバから来た板だけ**。その二つは §2 のとおり、
縦結合ぶんだけ無かったことになって崩れない。
