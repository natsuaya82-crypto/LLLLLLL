## 3. ⑫ 年額に取り消し線と 17% OFF ── **止めました。オーナーの判断が要ります**

```
49.99は取り消し線＋17%OFF
4はドル。でもさっき価格登録してきたけど日本円は800円とかになってたよ   OWNER 2026-08-26
```

### 3-1. 今どうなっているか ── 指示の前提より、ずっと進んでいます

指示には「StoreKit のコードはまだ一行も書かれていない」「今ハードコードなら嘘を
二つに増やすだけ」とありましたが、**そうではありません。**

- `www/store.js`（第26章）が StoreKit の窓で、`ios/App/App/LinguaStore.swift` が
  native 側です（`ec00697`）。
- `planPrice()`（`settings.js:513`）は**既に** App Store から値段を取っています:

```js
var cost = storeCost(p.id, yr) || t(yr ? p.yr : p.mo);   // Apple の displayPrice
var off  = storeOff(p.id)      || p.off;                 // 月と年の金額から計算
```

- `www/i18n` の `$4.99` `$49.99` は**fallback だけ**です ── ブラウザ、スクリーン
  ショット、まだ作っていない商品のとき。
- **17% はハードコードされていません。** `storeOff()`（`store.js:180`）が月額と
  年額の**金額**から `Math.round((1 - b/(a*12))*100)` で出しています。理由も
  書いてあります:「Apple rounds each storefront separately, so a year that is 17%
  off in dollars is not 17% off in yen」。オーナーの 800 円の話と同じことです。
- `npm run plan` は**既にこれを検査しています**: 偽の App Store を立て、¥750／¥6,000
  を返し、割引が PLANS の 17 ではなく **33** になることを見ています。

**つまり「17% OFF」は済んでいます。足りないのは取り消し線の元値だけです。**

### 3-2. 取り消し線は、今の材料では正しく出せません

要るのは「月額 × 12」を**その人の通貨で整形した文字列**です。`www` にあるのは:

| 来るもの | 例 | |
|---|---|---|
| `price` | `"¥750"` | 整形済みの文字列。通貨も書式も Apple のもの |
| `amount` | `750` | 数。**通貨コードも locale も付いていない** |

`amount * 12` を `www` で整形する道はありません。`price` の中の数字を書き換えるのは
「整形済み文字列への算術」で、`store.js` 自身と `LinguaStore.swift` の両方が名指しで
禁じています:

> Building "$" + a number is how an app ends up showing dollars to somebody
> being charged yen.  ── `LinguaStore.swift:167`

`$59.88` を直接書けば、オーナーが今日指した 800 円の人には嘘になります。

### 3-3. オーナー／リーダーへの問い（三つ）

**① 元値は native から取るのでよいか。** `ios/App/App/LinguaStore.swift` の
`products()` に一行足すのが唯一まっとうな道です:

```swift
/* Twelve months of this product, formatted by the App Store's own formatter,
   so a year's saving can be shown struck through without www ever building a
   currency string out of a number. Beside `amount` and for the same reason:
   the sum is Apple's to format, in Apple's currency. */
row["year"] = (p.price * 12).formatted(p.priceFormatStyle)
```

`www` 側はそれを受けるだけです（`store.js` に `storeWas()`、`settings.js` の
`term()` に `<s class="pwas">`）。**`ios/` も `store.js` も私の territory の外なので
書いていません。** `priceFormatStyle` は StoreKit 2 の API ですが、**Linux では
コンパイルできないので確かめていません。**Mac が要ります。

**② App Store が答えないとき、取り消し線に何を出すか。**
ブラウザ、スクリーンショット、まだ作っていない商品のときです。
- (あ) 何も出さない ── 嘘は絶対に出ませんが、ブラウザとスクショでは取り消し線が
  一度も見えません。
- (い) `www/i18n` に `plan.price.plus.was` = `"$59.88"` を足して fallback にする ──
  既に `$4.99` `$49.99` がそうなっている形と揃いますが、10言語ぶんの新しい鍵が要ります。

**私は決めません** ── `CLAUDE.md`「Deciding: 値段、無料と有料の境目 …
はここで決めない」。

**③ スタッフではあるが admin ではない人の通報キュー**（§1 の末尾）。
今それに当たる人はいませんが、`staff_add()` がある以上、いつか出ます。

### 3-4. これを持つべき検査

`tools/plan-check.mjs:534-545` に、この検査のための足場が既にあります ──
偽の App Store が ¥750／¥6,000 を返し、割引 33 を確かめる所です。
元値の主張はそこに足すのが正しく、`$59.88` ではなく **¥9,000** が出ることを
見る形になります（17 が出ると、どこから来たのか証明できないのと同じ理由）。
