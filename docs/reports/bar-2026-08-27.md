## 1. 先に調べたこと（リーダーの三つの問い）

### ① Capacitor 8 に設定はあるか → **ありません**

```
grep -rin "accessory" node_modules/@capacitor/     →  0件
```

`@capacitor/ios` の中でキーボードに触るものは
`WKWebView+Capacitor.swift` の `keyboardShouldRequireUserInteraction` 一つだけで、
これは**プログラムから focus したときにキーボードを出すか**の話で、帯とは関係が
ありません。`capacitor.config.json` に置ける項目もありません。

`@capacitor/keyboard` は入っていません（`package.json` は `core` と `ios` だけ、
Podfile も `Capacitor` と `CapacitorCordova` だけ）。リーダーの調べたとおりです。

### ② `MainViewController.swift` でどうするか → **公開された道はありません**

帯はアプリのものではありません。HTML にも CSS にも一切なく、WKWebView の中に
WebKit が置くビューの `inputAccessoryView` です。**読み取り専用**です。

- `WKWebView` 自身の `inputAccessoryView` を上書きしても出るのはこれではありません
  （出しているのは中の `WKContentView`）。
- `inputAssistantItem` は **iPad の**ショートカット帯を決めるもので、iPhone の
  この帯ではありません。

**この手を採ることはオーナーが決めました** ── 「真似よう。ダメなら諦める」
OWNER 2026-08-27。**後半も決定のうちで**、弾かれたら帯を消すのはやめます。

**App Store で通っている実物を読みました。** `@capacitor/keyboard@8.0.5` を
（プロジェクトには入れず）取ってきて `ios/Sources/KeyboardPlugin/Keyboard.m` を
読むと、`setHideFormAccessoryBar:` はこうです:

```objc
Method WKMethod = class_getInstanceMethod(NSClassFromString(WKClassString),
                                          @selector(inputAccessoryView));
IMP newImp = imp_implementationWithBlock(^(id _s) { return nil; });
method_setImplementation(WKMethod, newImp);
```

**つまり:「`UIResponder` の公開プロパティ `inputAccessoryView` の実装を、
非公開クラス `WKContentView` の上で差し替える」** ── これしかありません。
`_` で始まる Apple の非公開メソッドを呼ぶ、という意味での private API ではなく、
**非公開の「クラス」に手が届いている**という形です。区別は書いておきますが、
**リーダーが出した「private API を叩かない道」は、存在しません。**そこは
はっきりさせておきます。消せないなら消せない、が正しい報告なので、
**この関数を消す判断はリーダーとオーナーのものです。**

書いたもの（`ios/App/App/MainViewController.swift`）:

```swift
  private func hideFormAccessoryBar() {
    guard let contentView = NSClassFromString("WKContentView"),
          let getter = class_getInstanceMethod(contentView,
                                               NSSelectorFromString("inputAccessoryView"))
    else { return }
    let noBar: @convention(block) (AnyObject) -> UIView? = { _ in nil }
    _ = method_setImplementation(getter, imp_implementationWithBlock(noBar))
  }
```

死んでいる `UIWebBrowserView`（UIWebView のもの）の側は落としました。

**一つだけ真似していません。** プラグインはクラス名を
`@[@"WK", @"Content", @"View"] componentsJoinedByString:@""` と組み立てて、
文字列がバイナリに残らないようにしています。**こちらは名前をそのまま書きました。**
隠しても走るものは同じで、変わるのは見え方だけです。この repo が
「やっていることを偽装した側」になるのは違うと判断しました。
**受け入れられないなら、答えはこの関数を消すことで、名前を隠すことではありません。**

**2026-08-27、いちど「真似て隠す」指示が出て、撤回されました。**リーダーの言葉:

> 「ダメなら諦める」は「Apple に弾かれたらそれで終わりにする」ということで、
> 弾かれる結果を受け入れると言っている。文字列を隠すのは弾かれないために
> やることなので、**弾かれてもいいと決めた人が隠す理由は無い。**
> オーナーが決めたのは *swizzling という手を採ること* であって、
> *それを隠すこと* ではない。

**名前はそのままです。**この段落を消さないこと ── 次に読む人が
「なぜ隠していないのか」ではなく「なぜ隠さないと決まったのか」を読めるように。

**呼ぶ場所と、そのとき `WKContentView` が居るか。** `capacitorDidLoad()` です。
`CAPBridgeViewController.loadView()` を読むと `prepareWebView(...)` →
`view = webView` → bridge 生成 → `capacitorDidLoad()` の順なので、
**呼ばれる時点で WKWebView は既に在り、WebKit は読み込まれています。**

**静かに間違いません。** Apple がクラスを消すか改名すれば `guard` を抜けて
何も起きず、帯は画面に残ります ── それは今この瞬間、実機に出ている状態です。
`docs/keyboard-extension.md` の教訓（「まず画面に状態を出せ」）に対しては、
**失敗した状態が画面そのもの**なので、出すものがありません。

### ③ `✓` を消したらキーボードを下げる道が無くなるか → **投稿画面では、もともと下がりません**

`www/post.js:916` の `pwKeepKb()` / `pwKbGuard()` が、フォーカスが外れると
**戻します。**そのコメント自身がこう書いています:

> It goes down by the field losing focus, and there is no key on an iPhone that
> does anything else -- so putting it back is the whole of 「it cannot be lowered」

つまり投稿画面では `✓` を押しても一瞬で戻るので、**消しても失うものはありません。**
（引き継ぎ ②㉑ の「キーボードが下ろせる」への答えが、これです。）

**それ以外の画面**（単語、検索、設定の名前、サインインの扉）では `✓` が
下げる道の一つでした。消したあとは**フィールドの外を触れば下がります** ──
どの web view でもそうなる、普通の道です。**`www/` は一行も変えていません。**

## 2. カメラ・マイクの行 ── 直すところはありません

リーダーの読みが正しく、コードで裏が取れました。

```js
/* www/shell.js:663 */
d.setProperty('--vvkb',
  Math.max(0, window.innerHeight - h - (v? v.offsetTop : 0))+'px');
```

`--vvkb` は **visualViewport の下に残っている高さ**で、そこには
**キーボードとこの帯の両方**が入っています。`index.html:1076` の
`.view.fit .pwbar{bottom:var(--vvkb,0px)}` はそれに貼り付いているので、
**帯が消えれば行はキーの上に降ります。**`index.html` のコメントが既に
名指ししていました ── 「その隙間と、その下の iOS 自身の accessory bar が、
行が浮いていた元」。
