## 結論から: 幅は合っていました。壊れていたのは別のところです

タイルと、**そのタイルで実際に置いたキー**を、どちらもページに聞いて測りました
（`getBoundingClientRect()`、両方とも）:

| 盤 | タイル1 / 置いたキー | タイル2 / 置いたキー | タイル3 / 置いたキー | 高さ |
|---|---|---|---|---|
| qwerty | 28.2 / 28.2 | 60.5 / 60.5 | 92.9 / 92.9 | 44 / 44 |
| flick | 28.2 / 28.2 | 60.5 / 60.6 | 92.9 / 92.9 | 44 / 44 |
| tap · chart · abc | 同じ | | | |

`kbCellW()` は盤がキーを並べるのと同じ計算（十列固定の上での `kbU(w)`）です。
**幅1のタイルは、どこに落としても幅1のキーになります。**

### いただいた表の読み方について

> | フリック（4列に見える盤） | 本物のキー 76.7pt | タイル1 28.2pt |

**この二つは別の幅のものです。** フリック盤のキーは **幅2.5**（十列のうち5列を
跨ぐ）で 76.7pt、タイル1 が作るのは **幅1** のキーで 28.2pt。同じ幅どうしで
比べると一致します。

「合っていない」ように見えるのは正しい観察で、原因は幅の計算ではなく、
**その盤に幅1のキーを置く余地が無いこと**でした ↓

## 本当に壊れていたもの ── 置けないのにタイルが出ている

パターンの作る盤は**どの行も合計10**なので、**新品の盤ではどの幅のキーも
どこにも入りません。** 五つ全部で測りました:

```
満杯の行にタイルを置く   qwerty 1:10→10  2:10→10  3:10→10
                       flick  1:4→4    2:4→4    3:4→4
                       tap / chart / abc も同じ
1列消して空きを2つ作った後   タイル1 だけ入る（2 と 3 は4・6列分要る）
```

**何も throw しません。** タイルは光り、押したキーは何も開かず、行は行のまま。
**オーナーがその1時間前に列について言った「最大になったら+はなし」の、一段下の
同じ形です。**

### 直した

- `kbRoomAny(w)` ── その幅がこの面のどこかの行に入るか。`kbRoomIn()` を全行に
  聞くだけの一行です。
- 入らない幅のタイルは **消灯**。消してはいません ── シートの上の三つのボタンが
  何も選んでいないときにそうしているのと同じ扱いで、**「今は足せない」と
  「そんな機能は無い」は別のこと**だからです。
- `kbSetNew()` も断ります。見た目だけ消灯にすると、別の道から掴めます。

## 高さ ── **CSS の変更は要りません**

`.kbnewt` は `height:44px`、`.kbk` は `calc(var(--kh) * var(--rh))`。
`.kb.kbsheet` の `--kh` は 44px、`--rh` は `.kbrow` で常に 1 なので、
**どちらも 44px で、測っても 44/44 です。**

**`index.html` は一行も触っていません。**

## 検査

`tools/kb-check.mjs` に6項目。**`KB_PATS` をページに聞いて**全パターンぶん
（`press` と同じ理由 ── 六つ目が足された日に歩きます）。

**両方ページに聞いています。** 検査が幅を計算し直すと検査対象の写しになって
必ず一致する ── `CLAUDE.md` rule 10 の
「A check that recomputes the thing under test is a copy of it, and a copy
always agrees」。タイルは `getBoundingClientRect()`、キーも
`getBoundingClientRect()` で、間に本物の `kbSetNew()` → `kbPick()` が入ります。

**赤を三通り見ました:**

```
(1) 消灯を外す
    FAILED  every pattern comes to the full ten, so all three width tiles are down
(2) タイルの幅を盤の列数で割る（いただいた読みを実際に作った形）
    FAILED  and each is DRAWN the size of the key it makes:
            qwerty 31.8/28.2 76.7/60.5 134.5/92.9  flick 31.8/28.2 76.7/60.6 134.5/92.9 ...
(3) 置くキーの幅を無視する
    FAILED  and each puts in a key of exactly the width it says
    FAILED  ... 60.5/28.2 92.9/28.2
```

**(2) は、疑われた形を作れば検査が捕まえることの証明でもあります。**
