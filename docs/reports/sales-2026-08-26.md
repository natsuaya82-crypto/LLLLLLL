## 1. Apple の API が実際にどうなっているか

全部 Apple の公式ドキュメントで確かめました。出典は各項の末尾に。
**推測はありません。分からなかったことは「分からない」と書いてあります。**

### 1-1. 売上（①）と ダウンロード数（②）── **同期で取れる。毎回開くたびが成立する**

```
GET https://api.appstoreconnect.apple.com/v1/salesReports
```

- **同期**です。頼んで待つ形ではありません。1回の GET で本文が返ります。
- 返るのは **`application/a-gzip`** ── gzip で固めた **TSV**（タブ区切り）です。
  JSON ではありません。**展開してタブで割る必要があります。**
- 必須の絞り込みは四つ:

  | 名前 | 値 |
  |---|---|
  | `filter[reportType]` | `SALES` / `SUBSCRIPTION` / `SUBSCRIPTION_EVENT` ほか |
  | `filter[reportSubType]` | `SUMMARY` / `DETAILED` ほか |
  | `filter[frequency]` | `DAILY` / `WEEKLY` / `MONTHLY` / `YEARLY` |
  | `filter[vendorNumber]` | **§1-5 を読んでください。四つ目の鍵です** |

  `filter[version]` は任意ですが、**組み合わせは決まっていて自由ではありません。**
  ドキュメントの表をそのまま写すと:

  | reportType | reportSubType | frequency | version |
  |---|---|---|---|
  | `SALES` | `SUMMARY` | DAILY, WEEKLY, MONTHLY, YEARLY | `1_0` |
  | `SUBSCRIPTION` | `SUMMARY` | **DAILY のみ** | `1_3` |
  | `SUBSCRIPTION_EVENT` | `SUMMARY` | **DAILY のみ** | `1_3` |
  | `INSTALLS` | `SUMMARY` | **MONTHLY のみ** | `1_2` |

  外れると 400 です。**この表以外の組み合わせは無い**ので、コードは表を持ちます。

- **遅れは一日です。** Apple の言葉で「next-day data」。
  一日の区切りは **太平洋時間の 0:00–23:59** ── `daily-prompt/index.ts` の
  `pacificDay()` が既に同じ理由で同じことをしています（「Apple が App Store を
  動かしているタイムゾーン」）。**今日の売上は今日は取れません。**
- `filter[reportDate]` は DAILY では任意ですが、**省くと「最新のもの」であって
  「今日」ではありません。** 日付を明示して、無ければ前の日へ下がるほうが、
  何日のものを見ているのか画面が言えます。

出典:
- https://developer.apple.com/documentation/appstoreconnectapi/get-v1-salesreports
- https://developer.apple.com/help/app-store-connect/view-sales-and-trends/download-and-view-reports/

### 1-2. 解約と継続率（③）── **数は取れる。「継続率」という欄はどこにも無い**

`SUBSCRIPTION` / `SUMMARY` / `DAILY` / `1_3` が **その日の断面**です。
契約者数はここにあります（列名そのまま）:

```
Active Standard Price Subscriptions
Active Free Trial Introductory Offer Subscriptions
Active Pay Up Front Introductory Offer Subscriptions
Active Pay as You Go Introductory Offer Subscriptions
… ほか、オファー種別ごとに 17 列
```

解約は `SUBSCRIPTION_EVENT` / `SUMMARY` / `DAILY` / `1_3` の **`Event` 列**です。
取りうる値は 14 個あり、解約に当たるのは `Cancel` と
`Canceled from Billing Retry`、継続に当たるのは `Renew` と `Reactivate` です。

**⚠ 継続率（retention）そのものを返す欄は、どちらのレポートにもありません。**
出すなら**こちらで割り算します**。そして割り算には決めることが二つあります ──
**何を分母にするか**（前日の契約者数か、その月に始まった人か）と
**どの期間か**。`docs/FEATURES.md` § 8 の
「Not decided: what a number is called, what period it covers」がまさにこれです。
**決めていません。§3 で聞きます。**

出典:
- https://developer.apple.com/help/app-store-connect/reference/reporting/subscription-report/
- https://developer.apple.com/help/app-store-connect/reference/reporting/subscription-event-report/

### 1-3. App Store Analytics ── **「頼んで、あとで取りに来る」で当たり。四往復です**

`docs/FEATURES.md` § 8 の警告どおりでした。こちらは salesReports とは別物です:

```
1. POST /v1/analyticsReportRequests            ← 頼む（accessType: ONGOING）
2. GET  /v1/analyticsReportRequests/{id}/reports
3. GET  /v1/analyticsReports/{id}/instances     ← DAILY / WEEKLY / MONTHLY
4. GET  /v1/analyticsReportInstances/{id}/segments
5. その segment の url を落とす
```

ドキュメントの言葉:

> When making a request with this endpoint, the accessType `ONGOING` is most
> common and provides current data. This report request **generates reports
> daily**.

> The download URLs are valid for **5 minutes** after generating.

**「毎回開くたび」との関係を、混ぜずに書きます。**

- **1 は一度きり**で、毎回ではありません。頼んでおけば Apple が毎日作ります。
- **2–5 は同期**なので、**開くたびに叩くこと自体はできます。**
- ただし**中身は日次より新しくなりません。** 開くたびに取りに行っても、
  返るのは Apple が最後に作った日次のものです。

出典:
- https://developer.apple.com/documentation/appstoreconnectapi/post-v1-analyticsreportrequests
- https://developer.apple.com/documentation/appstoreconnectapi/get-v1-analyticsreportinstances-_id_-segments

### 1-4. 認証 ── **ES256 の JWT で合っています。有効期限の上限は 20 分**

ヘッダ `alg=ES256` `kid=<Key ID>` `typ=JWT`、
本文 `iss=<Issuer ID>` `iat` `exp` `aud=appstoreconnect-v1`。

> For most requests, App Store Connect **rejects a token with a lifetime
> greater than 20 minutes**.

`.p8` は PKCS#8 の EC 秘密鍵で、Deno の `crypto.subtle` が
`ECDSA / P-256 / SHA-256` でそのまま署名できます。**外の library は要りません。**

出典: https://developer.apple.com/documentation/appstoreconnectapi/generating-tokens-for-api-requests

### 1-5. ⚠ 鍵は三つではなく **四つ**要ります

`supabase/setup.md` § 10-2 は `ASC_ISSUER_ID` / `ASC_KEY_ID` /
`ASC_PRIVATE_KEY` の三つを挙げています。**`filter[vendorNumber]` が必須で、
これはその三つのどれでもありません。**

そして **API にはベンダー番号を教えてくれる口がありません。** 人が
App Store Connect の **「お支払いと財務レポート」**（Payments and Financial
Reports）の左上から読み取って、手で置くしかありません。

**`supabase/setup.md` § 10-2 に四つ目として `ASC_VENDOR_NUMBER` を足しました。**
これが無いと、鍵を三つ正しく置いても売上は 400 で返ってきません。

出典: https://developer.apple.com/documentation/appstoreconnectapi/get-v1-salesreports
（`filter[vendorNumber]` は required）

## 2. で、「画面を開いたときに毎回」は成立するのか

**成立します。ただし「毎回取りに行ける」であって「毎回新しい」ではありません。**
この二つは別のことで、混ぜると嘘になるので分けて書きます。

| | 開くたびに取りに行けるか | 中身の新しさ |
|---|---|---|
| ① 売上 | **はい**（同期の GET 一本） | **前日まで**（太平洋時間） |
| ② ダウンロード数 | **はい**（同じ一本） | **前日まで** |
| ③ 契約者数・解約 | **はい**（同期の GET 二本） | **前日まで** |
| ③ 継続率 | 割り算はこちら | **決まっていません（§3）** |
| Analytics | 2–5 は**はい**、1 は一度だけ | **日次**、最初の一回は Apple が作るまで待ちます |

**だから、オーナーの決定「画面を開いたときに毎回」は、Apple の側では
何も邪魔していません。** 取りに行く回数の話であればそのとおりに作れます。
**引っかかるのは「毎回」ではなく「今日の数字は無い」ほうです** ── 画面には
必ず**いつの日の数か**が要ります。そうでないと、昨日の数を今日の数として
見ることになります。これは説明文ではなく、その数が何の数かという事実です。

**なので ①②③ は salesReports 三本だけで建てます。** Analytics（四往復のほう）は
**建てていません** ── ①②③ に要るものが salesReports で全部揃うからで、
ダウンロード数も `SALES` レポートの `Units` にあります。Analytics が要るのは
それ以外の指標（表示回数、クラッシュ、など）を出すと決めたときで、
**それは決まっていません。**

## 3. 決めていないこと ── オーナーに聞くところ

`CLAUDE.md`「Deciding」に当たるものだけを並べます。**こちらでは決めていません。**
今日の画面は「Apple が返した粒度をそのまま出す」で作ってあり、
どれも**答えが出てから直せば一行か二行**です。

### 3-1. 通貨 ── いま「足していません」

`www/store.js` と `ios/App/App/LinguaStore.swift` が同じ文で禁じています:

> Building "$" + a number is how an app ends up showing dollars to somebody
> being charged yen.

Apple は**国ごとに、その国の通貨で**払います。売上レポートは
`Developer Proceeds` と `Currency of Proceeds` の組で返ってくるので、
**一つにまとめるには為替が要り、為替はこのリポジトリにありません。**
Apple もくれません（くれるのは「いくら払ったか」であって「今いくらか」では
ないので）。

**今こうなっています ── 通貨ごとに一行:**

```
売上    JPY 700
売上    USD 3.49
```

**選択肢:**

| | |
|---|---|
| **A. このまま**（通貨ごとに一行） | 嘘が一つもない。国が増えると行が増える |
| B. 円だけ出す | 一番読みやすい。**他の国の売上が画面から消えます** |
| C. 為替を入れて円にまとめる | 一行になる。**為替 API という外部の鍵がもう一つ増えます**。しかも Apple が実際に払う額とは一致しません |

**A で置いてあります。**「一つの数にしない」がいちばん壊れないからで、
B や C にするのはオーナーの判断です。

### 3-2. 継続率 ── いま「率は出していません」

**どちらのレポートにも継続率という列はありません**（§1-2）。出すには
二つ決める必要があります:

1. **何を分母にするか** ── 前日の契約者数か、その月に始まった人か
2. **どの期間か** ── 1日か、1ヶ月か、初回から N ヶ月後か

**今こうなっています ── Apple が数えた数だけ:**

```
契約    21     ← その日に生きている契約
継続     9     ← その日の Renew の件数
解約     3     ← Cancel と Canceled from Billing Retry
```

この三つがあれば率は後からいつでも足せます。**逆に、率だけ出すと元の数が
見えなくなります。**

### 3-3. 数の呼び名

`docs/FEATURES.md` § 8 の「Not decided: what a number is called」です。
今は日本語で 売上／ダウンロード／契約／継続／解約／日 としてあります。
**ダウンロードは特に確認をお願いします** ── Apple は三つを別々に数えていて、
今出しているのは一つ目だけです:

| | いま |
|---|---|
| 初めて入れた人 | **これを「ダウンロード」として出しています** |
| 入れ直した人（`3` `3F`） | 数えてはいるが画面に出していません |
| アップデート（`7` `7F` …） | 同上 |

どれを「ダウンロード数」と呼ぶかで数字が変わります。分類は Apple の表
そのままで、こちらで決めた分け方ではありません
（https://developer.apple.com/help/app-store-connect/reference/reporting/product-type-identifiers/ ）。

### 3-4. 鍵が入っていないとき、画面は「空欄」です

`CLAUDE.md`「アプリ内に説明書くの禁止」に従って、**画面には理由を出していません。**
鍵がまだのときも、Apple にその日のレポートがまだ無いときも、同じ空欄です。
理由は `supabase/setup.md` § 10-5 の表と、Edge Function の Logs で見ます。

**これでよければこのままです。** ここは 2026-08-22 の narrowing
（「必要な説明は書いてね。みてわからないのが一番ダメ」）に当たるかもしれない、
と思ったところです ── ただし narrowing は「アプリが何かを取り上げた画面」に
限られていて、ここは何も取り上げていないので、**書かない側に倒してあります。**

## 4. 画面のどこに何を置いたか

⚠ **`docs/FEATURES.md` § 8 は「画面がどう見えるか」を「決まっていない」と
書いています。だからこれは提案です。「こう置いた、これでよいか」を聞いています。**

**新しいルートは作っていません** ── `www/shell.js` の `PAGES` は他のセッションが
持っているファイルなので触っていません。既にある管理画面（`vAdmin`）の
`adminRow` の列に足しただけです。

```
  人        1,204        ← もとからあった四つ
  投稿      8,821
  言語        932
  通報          3   ›
  売上     JPY 700       ← ここから下が今回
  売上     USD 3.49
  ダウンロード     3
  契約          21
  継続           9
  解約           3
  日     2026-08-25
  スタッフ                ← もとからあった
  @lingua
```

- **`adminRow()` をそのまま使っています。** 行の高さも見た目も、
  設定画面の行と同じものです。新しい CSS は一行も足していません
  ── `CLAUDE.md`「NO ROUNDED BOX」と「Rows in one list are one height」
- **「日」は要ります。** Apple のデータは前日ぶんまでなので、日付の無い数字は

  その数が何の数かという事実です
- 三つのレポートは Apple の側で別々に用意されるので、**日がずれたときは
  両方出ます**（`2026-08-23 / 2026-08-25`）。一つ選ぶと残り二つについて
  嘘になるので
- **押せる行は増えていません。** 全部ただの行なので、`press` の
  `buttons pressed` は動かないはずです
