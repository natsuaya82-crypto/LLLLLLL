# claude/other ── オーナーが実機で踏んだ六つ（オンライン側）。報告

枝: `claude/other`。実機は iPhone SE2（320pt）と iPhone 17。

## 一行

**六つのうち三つは「一人しかいない世界」では絶対に出ないバグで、そのうち一つ
（人の検索）は誰に対しても何も返していませんでした。**二つはしきい値なので
決めていません。一つはサーバー側の決定待ちで、扉を閉じた所で止めています。

## いちばん読んでほしいところ ── 検索は「新しいアカウントが」ではなかった

オーナーの言葉は「新しいアカウントが検索に出てこない」でした。**新しいから
ではありません。誰も出ていませんでした。**

`netFindWho()` はこう訊いていました:

    /rest/v1/profile?select=id,handle,display,av,language(name)

`language(name)` は embed で、PostgREST は**外部キーを歩いて**そこへ行きます。

- 2026-08-19（`52d23e1`）にこれが書かれた時は通っていた ──
  `language.owner` が `references profile(id)` だったから
- 2026-08-22（`2f214ba`）に、profile 行を持たない無名アカウントが言語を持て
  るように **`auth.users(id)` へ張り替えられた**。正しい変更で、データベース
  の話。それが、ネットワークの話の文字列から道を奪った

いま両方 `auth.users` を指していて互いを指していないので、PostgREST は繋げ
ません。**そして embed が解けないとき、行だけ返して embed を諦めるのではなく、
要求ごと PGRST200 / 400 で断ります。**つまり「言語の無い人」ではなく**誰も**。

**六日間、誰にも見えませんでした。**`tools/fixture.mjs` が `netFindWho()` の
**答え**を手で置いているからです（walk にサーバーは無いので、正しい判断です）。
**問いそのものを通すものが一本も無かった。**

### 1. プロフィールが「？」（`0e3dfc8`）
人のページに出るものは全部その人の**投稿**から取っていた（`whoOf()` が `POSTS`
を歩く）。検索から見つけた人はこの端末が持っている投稿を一つも書いていない
ので、ループは端から落ち、`postFace()` は名前の無い人を受け取って「？」を描く。
Follow ボタンの付いた疑問符が一枚、それがページでした。

`netWho()` で profile 行を handle から引きます。返るのは**いまその人がどう
見えるか**で、`schema.sql` が `profile.av` の所で書いている区別そのもの ──
投稿は書かれた瞬間に自分の顔を凍らせる（規則8）、こちらは凍らせない。

bio とフォロー数は入れていません。**`profile` にその列が無い**ので。0 を描くと
教わっていないことをプロフィールが言い出します。

### 3. 検索（`3429a51`）
embed をやめて二回訊く形に。`profile.id` と `language.owner` は同じ uuid（どちら
もアカウント）なので手で訊けます。`netFeed()` がフォロー一覧を別に訊くのと同じ形。
**名前は飾りで人が答え**なので、言語の問いが落ちても人は返します。

### 4. フォロー0（`05a53ea` ＋ `35af082`）
**正しい0ではありませんでした。**二段階でした。

`netFeed('fo')` はサーバーの `follow` 表から答えを返しますが、その答えを
`snsMine()` が `ME.fo` でもう一度ふるっていた。`ME.fo` は**この端末で押した
とき**だけ書かれ、サーバーから埋める処理がどこにも無かった。二台目に入ると
空なので、正しく届いた投稿が全部そこで落ちる。**オーナーが SE2 と 17 の二台で
確認しているのは、それを作る二台そのものです。**

- `05a53ea` ── サーバーが選んだ答えをそのまま出す（ふるいを外す）
- `35af082` ── `ME.fo` 自体をサーバーから埋める（`netFollowing()`）

### 6. 通知（`55e66dc`）── 半分
行の顔と、顔からその人のページへ。新しく描かず `postAvHTML()` を呼びます ──
タイムラインは 2026-08-26 に同じ答えを出していて、通知だけが同じ顔を景色の
ままにしていた。

**未読の数は入っていません。**`tabBar()` は `www/shell.js` で、持ち物では
ありません。しきい値（どこから未読か）でもあります。

### 2. 扉を閉じた（`10b2e08`）── **直っていません**
人の言語名のボタンが `go("about")` を**誰の、を付けずに**呼び、開く先の
`wldPage()` は `world()` `LETTERS` `langName` ── 全部**開いている言語**を
描いていた。人の言語名を押すと、その人の名前を頭に載せた**私の言語**が出る。
規則8そのもの、しかも言語を読む唯一の画面の上で。

名前は残して押せなくしました（非公開のときに `wldRow()` が取るのと同じ形）。
**押すと私の言語が出る状態よりは良い、というだけのものです。**

## 直していないもの ── 理由つき

### ② の本体はサーバー側の決定
記事は `wld` スライスで、`slice_read` は `l.owner = auth.uid()`。**他人の言語は
公開されていても一行も読めません。**

これは書き落としではなく**決めてあること**で、四か所に同じ文があります ──
`schema.sql:597`、`tools/rls-check.mjs:270`、`docs/FEATURES.md:588`、
`docs/CHANGELOG.md`。「publishing is a copy somebody is given and **not a door
into the phone**」。

`rls-check` には**それを突く行が既に在ります**（`'B cannot read a published
language's slices'` → denied、および `slice` の SELECT 政策で
`owner = auth.uid()` を含まないものは 0本、という形の主張）。**緩めるにはこの
二本を消すことになります。**検査を消して自分の機能を通す形は、いつでも間違い
です。`docs/FEATURES.md` は先回りして「**a question, not a gap to close**」と
書いています。

**さらに、緩めても今日は何も開きません。**`published_at` を書くコードが `www/`
に **0 本**です。言語は一つも公開されていないので、`published_at is not null`
を条件にした政策は誰にも何も開けません ── 緑になって端末では何も変わらない。

（リーダーから一度 `schema.sql` を渡されましたが、上を報告して**撤回されて
います**。一行も変えていません。）

### ⑤ おすすめ0 ── 正しい0
`feed_hot()` は `created_at <= feed_slot()`、`feed_slot()` は**今の4時間の
区切りの頭**。区切りより後に書かれた投稿は入りません。`schema.sql` 自身が
「a post written a minute ago is not in this list … That is the shape that was
asked for」と書いています。投稿が数時間内のものしかない状態（新しい環境、
二台目、投稿した直後）では**必ず 0**。窓を動かすのはしきい値なのでオーナーへ。

（`schema.sql:1005` のコメントは「12時間ごと」ですが、リーダーが
`docs/FEATURE_RULES.md` の決定ログで**4時間ごと**を確認済み。**コードが正しく、
コメントが古い。**`rls-check` も「the list turns on a four-hour tick」を主張
しています。schema.sql は触っていないので、コメントは古いままです。）

## 足した検査 ── 一本

**`tools/sides-check.mjs` 規則三本目:「embed は外部キーを歩くこと」**

**答えではなく、組み立てた URL を見ます。**`net.js` の select から embed を
入れ子ごと拾い、`schema.sql` の外部キーを Postgres が読む順（inline →
alter の drop/add、drop されて足し直された制約は add が勝つ）で組んで照合。
両方向と、**列の名前で辿る形**（`report` の `who(...)` が `profile` へ行く形）
を見ます。**サーバーは要りません。**

手で置いた答えは「サーバーはこう言うはず」という主張であって、**このバグは
こちらが何を訊くかに住んでいます。**だから答えの側では永久に見つかりません。

**バグを戻して赤を見ました**（4本中1本、exit 1）。戻して緑。
失敗時に「every one with a foreign key behind it」と言い続けないよう、
数え方も直しています（自分自身と言い争う検査にしないため）。

**そして直後に働きました** ── ④で足した `followed(handle)` を自動で見ています
（`follow` は `profile` への外部キーを二本持つので、表ではなく列の名前で
訊く必要がある所です）。いま 4本中 4本。

## ついでに見つけて直したもの

`postFace()` は描いた顔を `p.id` で控え、**無ければ 'me' に落ちます**。
`whoOf()` が返す人は `id` を持っていなかったので、**自分で文字を描いた人の顔が
私の鍵の下に仕舞われていました。**ページに顔が一つしか無いことが、まだ表に
出ていなかった理由でしかありません。鍵を handle にしました（`0e3dfc8`）。

同じ形が通知にもあったので、そちらは入れる前に避けています ── 通知の `id` は
「何についての通知か」＝投稿なので、同じ投稿にいいねした二人が一つの鍵を
分け合い、フォロー（投稿を持たない）は 'me' に落ちます（`55e66dc`）。

## 見つけたが直していないもの（六つの外）

`snsList()` は 'rec' で `postAll()` を返し、これが `at` の降順に**並べ直し
ます**。`feed_hot()` はスコア順で答えていて `netFeed()` 自身が「順序はサーバー
の答え」と書いているのに、**おすすめタブはその順序を捨てています。**

直しませんでした ── 直すと「サーバーが返したものだけ」になり、⑤の窓が今の
ままだと**画面が今より空になります**。窓の判断（オーナーのもの）と一緒でないと、
直したほうが悪く見えます。

## 最初のコミットで直したもの

`origin/claude/other` の Scope コミットに **`node_modules` が mode 120000 の
シンボリックリンク**で入っていました（中身は絶対パス
`/home/user/LLLLLLL/node_modules`）。外しました（`9c65cf3`）。

**入ってきた穴も塞いでいます:** `.gitignore` の `node_modules/` は末尾スラッシュ
付きで**ディレクトリしか照合せず**、シンボリックリンクは blob なので素通りして
いました。スラッシュ無しの行を足しています。

## 保存するものの変化

**一つだけ:** `ME.fo`（`lingua.me` の中）が一セッションに一度、サーバーの一覧で
**置き換わります**（足し合わせではない）。向こうの端末で外したフォローは
「消えた行」で、足し合わせでは「まだ聞いていない行」と見分けられないため。

移行なし、削除なし。端末にしか無かったフォローはサーバーにも在ります
(`netFollow()` が最初から送っていた)。答えが空中にある間に押されたら書きません。

`docs/CHANGELOG.md` に記録しました（`CLAUDE.md` §Recording が必須と書いている
ため）。**CHANGELOG は宣言した持ち物の外です** ── 不要ならその hunk を落として
ください。
