## 結論 ── 盤ごと一つの grid にはしません。三行で済みます

「一つの grid にして `grid-row: span 2`」は正しい解ですが、**採りません。**
`www/index.html` はいま五本が触っています。盤の構造を書き換えると、行の
`<div>` が消えて `.kbrow.sel::before`（行の帯）と `.kbhdr` が巻き添えになり、
五本全部と衝突します。

代わりに、**キーが自分の行からはみ出して下の行を覆う**形にします。DOM は
「このキーは1行目のもの」と言ったままで、それは本当のことです ── 下の行に
残る `{k:'gap', up:1}` の影が、下の行のキーを動かさずに場所を空けます。

## 入れてほしいもの

**1. 行の隙間に名前をつける**（264行）

```css
/* いま */
.kb.kbsheet{width:var(--kbw);margin:2px auto 0;--kh:44px;gap:5px}
/* して欲しい */
.kb.kbsheet{width:var(--kbw);margin:2px auto 0;--kh:44px;--kbrg:5px;gap:var(--kbrg)}
```

5 が二箇所に書かれるのを避けるためです。二行ぶんの高さは
「キー2つ＋隙間1つ」なので、隙間の数を知っている必要があります。

**2. 行の高さを固定し、キーを伸ばさない**（271行のあたり）

```css
/* 足す */
.kb.kbsheet .kbrow{height:var(--kh)}
/* いまの行に align-self:start を足す */
.kb.kbsheet .kbk{min-width:0;margin:0 calc(var(--kbgap) / 2);align-self:start}
```

**これが要です。** 無いと壊れます（下に測ってあります）。grid の行は中身に
合わせて伸びるので、キーを高くすると**行そのものが伸びて下の行が押し下げられ、
同じ行の他のキーまで背が伸びます**。

**3. すでにある高さの式を一般化する**（328行）

```css
/* いま */
.kbk{position:relative;min-height:calc(var(--kh) * var(--rh));...
/* して欲しい */
.kbk{position:relative;min-height:calc(var(--kh) * var(--rh) + var(--kbrg, 0px) * (var(--rh) - 1));...
```

**新しいセレクタは足しません。** `--rh` はもう `.kbk` が読んでいる変数で、
`.kbrow` が `--rh:1` を置いています。結合したキーには `keyboard.js` が
`style="--rh:2"` を直接書きます ── そこは私の file です。

`--kbrg` はシート以外の板では宣言されていないので `0px` に落ち、
`--rh` が 1 なら `+ 0px * 0` になって**何も変わりません**。

## `press` は引っかかりません

「一つの list は一つの高さ」は、`tools/press.mjs` 289行で
**字の大きさが二種類あるときだけ**赤にします（「型が一つなら、ただ背の高い行で
あってこの欠陥ではない」）。結合キーは隣と同じ字なので素通りします。
**これは推測ではなくコードを読んだ結果です。**

## 一つだけ、見てから決めること

下の行が**選ばれている**とき、その紫の帯（`.kbrow.sel::before`）が結合キーの
下半分の上に描かれます。`.kbrow` は `position:relative` で z-index が auto
なので重ね順は DOM 順になり、後にある下の行の帯が勝ちます。

**これは直すべきか、正しいのか分かりません。** 下半分はその行のものでもあるので、
帯が掛かるのが正しいとも言えます。要らないなら `keyboard.js` から
`style="--rh:2;z-index:1"` と書けば消えます ── `index.html` は要りません。
**見てから決めてください。**
