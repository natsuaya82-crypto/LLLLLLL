# 一部 ── 実機の写真から

## 4. 返事がスレッドに来ない ── 直りました

**原因（押して確かめました）。**投稿には名前が二つあります。`id` は
このアカウントの端末が呼ぶ名前、`sid` はサーバーが置いている場所。**自分で
書いた投稿だけこの二つが違います**（届いた投稿は `netRow()` が両方を同じに
する）。相手の返信は `to` にサーバーの名前を入れて届き、スレッドは手元の
名前で開かれます。`postKids()` は渡された文字列と `to` を比べていたので、
**一つの会話が二つの束に分かれていました。**

再現：自分の投稿に `sid` を付け、`to` がその `sid` の返信を足す。ホームには
出る、スレッドには出ない。オーナーの `4-home.png` と `3-thread.png` が
そのままこれです。

**直し。**`postIs(p, id)` が「この名前はこの投稿のものか」を答える一箇所に
なり、`postById()` と `postKids()` の両方がそれを聞きます。名前で比べていた
行を消して書き換えました。**通知が運ぶのはサーバーの名前なので、通知から
自分の投稿のスレッドを開くと「ありません」だったのも同じ一行で直ります。**

- ファイル `www/post.js`
- 保存 変わりません

## 1・2. フォロー中の一行目が `?`、札が無い ── 直りました

**リーダーの見立てと違います。一番と二番は別のバグではなく、同じ一行です。**

一行目には**フォローボタンもありません**。ボタンが消えるのは `p.mine` が
真のときだけで、`p.mine` は `h===meHandle()`。**つまり一行目はオーナー
自身**です。自分は自分をフォローできないので「フォローされています」は
付きません ── 札が無いのは正しく、**その行がそこに在ること自体が誤り**です。

`supabase/schema.sql` の `follow` は `check (follower <> followed)` を持って
いるので、**サーバーはその行を持てません**。写し (`ME.fo`) が持っていました。
`meFollow()` は自分の handle を弾きますが、`meHandle()` は profile に handle
が無いとき**言語の名前**に落ちるので、今日答える handle が、行が入った日の
handle とは限りません。

**直し二つ。**
1. `whoOf()` の最初の答えが ME になりました。`whoPull()` は「それは ME、
   ここにある」と書いて止まっていて、**その ME を読むコードがどこにも
   ありませんでした**。自分の投稿を手元に持っている間だけ名前が出ていた
   （投稿から拾っていた）ので誰も気づきませんでした。押して再現しました。
2. `meFollowing()` と `meFollowers()` ── **両方の一覧が読まれる唯一の場所**
   ── で自分を外します。行の側で外すと数字が二のまま一行になります。

**自分の行は、相手のフォロワー一覧には正しく出ます**（その人をフォロー
していれば自分はそこにいる）。写真がそれです。

- ファイル `www/me.js` / 保存 変わりません（`ME.fo` は書き換えず、読むときに外す）

## 7. 数字が合わない ── 仕様を入れ、聞き直せるようにしました

**オーナーの仕様。**「サーバーに聞く前にロードを挟み、遅れて数字が動くことを
絶対に無くす。0 と出て1秒後に1に変わる、をしない。」

二つの数はどちらも一覧の**長さ**でした。誰も答えていない一覧は空なので、
**どのプロフィールも 0 と出してから本当の数へ飛んでいました。**`ME.fo` が
配列であること自体が「答えが来た」で、フォロー無しの 0 は本当の 0 なので
そのまま出ます。無い間はタイムラインと同じ回る印が立ちます。相手の側の
`p.fo||0` も外しました ── 投稿は数を運びません。

**「3フォロワーなのに2人しかいない」の確かな原因を一つ見つけました。**
`meFollowerPull()` は**アプリを開いている間に一度しか聞きません**
（`FR_ASKED`）。新しいアカウントを作ってフォローしても、その回の起動中は
数にも一覧にも出ません。オーナーの「新アカウントは？つくし」に合います。
**引っ張って更新（下）で聞き直せるようにしました。**

**確かめていないこと。**数と一覧が別の問い合わせから来る道
（`profile_seen` の数 と `netFollowers(handle)` の一覧）で片方だけ落ちる
かどうかは、サーバーのデータが要るので再現できていません。

- ファイル `www/me.js`、`www/index.html`（`.numwait`）

**タグは本文の文字になりました。**昼の形は `t('day.tag')` の十言語ぶんで、
アプリが投稿の横に一行として描くものでした ── 人は打てず、十の言い方に
割れ、検索は `netFindPrompt()` が**その日のお題しか名指しできない**ので
前の日が出ませんでした。それが「今日しか出ない」の正体です。

**消したもの（足していません）。**`dayTag()` `dayTagId()` `postTagHTML()`
`netFindPrompt()` `snsJoin()`、十言語ぶんの `day.tag` の鍵。
リーダーの言うとおり、その上に乗っていた二つ目の仕組みごと消しました。

**入れたもの。**
- `DAY_TAG`（`www/sns.js`）── 綴りは一つ。翻訳しません。
- `tagHTML()` ── 人が書いた言葉を描くところ**全部**で `#…` を拾って
  青い押せる言葉にします（行、意味、返信先の引用）。**一箇所**です。
- `snsTagGo()` ── 押すとその文字が検索の箱に入るだけ。答えはふつうの検索の
  答えなので、**前の日も出ます**（`netFindPosts()` は前から `body->>ln` と
  `body->>mn` を当たっています）。

**お題から書き始めると、行（本文）にタグが入っています。**打てる欄なので
**外せます**。押して確かめました。

**「集めるのは列」は消えていません。**`post.pr`（OWNER DECISION 2026-08-23
#6）はそのままです。タグを外しても、その日に答えたことは投稿に残ります。
**意味はお題の下では読み取り専用のまま**（同 #5）。タグが入るのは**行**で、
意味ではありません。

**角丸も枠も塗りもありません。**青い文字だけ。色は `--tag` で、二つのテーマ
両方に置きました。`box-check` 緑。

- ファイル `www/sns.js` `www/post.js` `www/net.js` `www/act-map.js`
  `www/index.html` `www/i18n/*.js`（十ファイルから鍵を一つ削除）
- 保存 **形は変わりません。**増える欄も消える欄も、移行もありません。
  変わるのは、お題から書いた投稿の `body.ln` の先頭にタグの文字が入ること
