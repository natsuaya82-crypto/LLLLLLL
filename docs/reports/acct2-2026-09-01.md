### 2. 別のアカウントで入っても、前のアカウントのものが出る

```
あと違うアカウントでログインしてんのに前のやつ出てくるんだけど？前のアカウント消えたんだが？
```

**まず測りました。失われたものは一つもありません。**

- **端末の写しは上書きされていない** ── `syMerge()` は相手側が空なら `mine` を返す
- **サーバーにも残っている** ── `language_read` / `slice_read` は持ち主にしか開かない

**原因は三つ別々にありました。**

1. **`lingua.langs` が持ち主を持っていなかった。** `LANGS[id]` は
   `{name, mine, sid}` で、`mine` は「この端末で作っているほうか」であって
   アカウントではありません。→ `uid` を足しました。
2. **`netLangRow()` が、目の前の言語をいま入っている人のもとに作っていた。**
   A が一度も上げていない言語に B が入ると、**写しではなくその言語が B のもの
   になります。**→ 四つの状態を別々に答えます（自分／他人は断る／`uid` 無し
   `sid` ありは**サーバーに訊く**／どちらも無ければ引き取る）。
3. **アカウントの言語を降ろす道が一本も無かった。** → `netLangsDown()`。
   **無いものを埋めて止まります**（`docs/DATA_SAFETY.md` 第2則）。

**そして半分は別の場所にありました** ── `netOut()` は Lingua のトークン二つを
外すだけで、**social provider 自身のセッションは生き残ります。**だから次に
Google を押すと誰にも何も訊かれず同じアカウントが返り、「サインアウトして別の
アカウントで入る」という道が**存在しませんでした**。`SocialLogin` は `www/` 全体で
一箇所にしか現れず、`logout` はどこからも呼ばれていませんでした。
→ `obSignOutSocial()`。

### 3. Google のボタンを押しただけでログインできる

**セッションは本物でした。** `SESS` が書かれる場所は `netTook()` 一箇所だけで、
入る値は Supabase の token 応答。Google の id_token は Supabase が Google の
公開鍵と audience で検証します。**押すだけで入れるのは「Google でログイン」が
そういうものだからで、そこは穴ではありません。**

**穴は隣にありました。** `netTook()` は access token さえあれば refresh token
無しでも取っていて、`rt` が `''` になります。すると `netSignedIn()` が偽
（**41 箇所が訊いています**）、`netRead()` は次の起動で黙って捨てる ── 画面は
「ログインしました」と言った後で。**これが「立っていないのに立ったように見えて
いる」唯一の形**でした。両方揃って初めてセッション、にしました。

### 4. Google の nonce

```
Passed nonce and nonce in id_token should either both exist or not
```

Supabase は provider で分岐せず、**送られた nonce を SHA-256 して id_token の
nonce クレームと比べ**、片側だけ在ると断ります。このアプリは両側とも送って
おらず、それはそれで揃っていました ── **Apple がいま通っているのがその証明です。**
Google のトークンにだけ、誰かが nonce クレームを付けていました。

**§0 を先に確かめました:** 受け取った `www/onboard.js` は nonce を渡していません
（`grep` はコメント一行だけ）。なので `docs/scope/claude-nonce.md` の **§3-B**。

**原因は今も分かっていません。** それでも B は効きます ── こちらが握れば、誰が
付けていようと**中身はこちらのものになり、両側が揃います。**

**渡された SHA-256 の実装に欠陥があったので直しました。** BMP の外（絵文字）を
**四バイトではなく三バイト二つ**として符号化していて、他のどの SHA-256 とも違う
答えを出します。今日これに当たるものはありません（`netNonce()` が食わせるのは
UUID）── **だからこそ、気づかれずにそこに在り続けたはずのものです。**

### 5. プランとキーボードと言語を、アカウントに結びつける

```
課金とアカウントとキーボードはアカウントに結びつく。
じゃないとアカウント変えたら無限に言語作れるやん
```

- **`plan` 表**（`supabase/schema.sql`）。**`profile` の列にはしていません** ──
  `profile_read` は `using (true)` で、列にすれば**全員の段が時間軸の読者全員に
  公開**されます。何も throw しません。
- **`netPlanSync()`** が起動時に読み合わせ、**高いほうの段を採ります**
  （`LinguaStore.swift` の `best()` と同じ規則）。サーバーの答えをそのまま採ると
  **領収書を持っている端末から段を取り上げます。**
- **`netPlanUp()`** は `capLapse()` から。**段が動いた唯一の場所**で、ボタンでも
  領収書でも失効でもそこに来ます（`www/store.js` の既存コメントがそう書いて
  います）。おかげで持っていない `store.js` に一行も触っていません。
- **`langCount()`** が、そのアカウントの言語を数えます。持ち主の書かれていない
  項目は**誰から見ても数に入ります** ── 厳しいほうで、緩いほうがオーナーの言った
  穴だからです。

## 実機でしか分からないこと

**誰も見ていません。**

1. **課金（`PLAN_BUY=true`）** ── StoreKit は Linux で動きません。**商品 4 つが
   App Store Connect に登録されていないと、実機では段を一つも買えません**
   （`docs/apple.md` §4、オーナーにしかできない）。無い商品を頼むと StoreKit は
   「そんな商品は無い」と答え、段は `free` のままです。**それが正しい状態です**
   ── 誰でも Pro を付けられるほうがはるかに悪い。
2. **Google の nonce** ── 通ったかどうかは押してみるまで分かりません。
   **外れた場合に画面に何が出るかは `docs/scope/claude-nonce.md` §7**：
   `netIdWhy()` が丸かっこで**どちら側に nonce が在るか**を足します。
   `(nonce id_token:n sent:y)` が出たら、渡し方が効いていません。
3. **Apple のサインイン。** 壊していないことを三通りで確かめました ──
   `obSignInApple` が**一バイトも同じ**／`onboard.js` の差分でコードとして
   `apple` に触れる行は `obSignOutSocial` の `who=['apple','google']` だけ
   （**サインアウト**の道）／`acct-check` 26 が偽のプラグインで
   `obSignInApple()` を**実際に走らせ**、両側とも nonce が無いことを見ています。
   **逆向き（Apple にも足す）を入れて赤も見ました。**それでも**実機では誰も
   押していません。**
4. **サーバーには当てていません。** `plan` 表・`profile.bio`・`profile_seen`・
   `post_seen` の五列・`feed_hot`/`feed_fo`・`notices()` は
   **`supabase/schema.sql` に書いてあるだけ**です。当て方は
   `docs/scope/claude-acct2.md`（SQL Editor に丸ごと貼る。全体が何度でも流せる
   ことは `rls-check` が二度流して確かめています）。
