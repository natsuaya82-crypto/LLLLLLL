# ② 毎回ファイルに保存 ── 測ってから直しました

## 今どうなっていたか（読んで確かめた結果）

**書き出しは以前からファイルに落ちていました。** 共有シートでも `<a download>`
でも、画面に持っているだけでもありません:

```
shMake()  → Capacitor.nativePromise('LinguaShare','sheet',{name, b64})
          → LinguaShare.swift : Documents/Sheets/<name>.pdf に .atomic で書く
          → 上書きしない。二枚目は `<name> 2.pdf`、三枚目は `<name> 3.pdf`（999まで）
```

`UIFileSharingEnabled` と `LSSupportsOpeningDocumentsInPlace` は `Info.plist` に
あるので Files から見えます。

**`www/wordsheet.js` の CSV が踏んだ罠は、この道には最初からありません。**
あちらは `<a download>` で、WKWebView が黙って無視し何も投げないので `try` が
必ず通り、毎回「書き出しました」と出ていました。`www/sheet.js` に
`<a download>` は一つもありません。`docs/BACKLOG.md`「電話からファイルが出て
いく道が二本ある」は `www/card.js` と `www/wordsheet.js` の話で、**用紙は
そこに数えられている二本のどちらでもありません。**

`keep()` との違いも書いておきます。`keep()` は前の世代を `.1` `.2` に回すので、
いずれ古いものが落ちます。**用紙は回しさえせず、書いたものが一つも動きません。**
Files で開いてペンで書いた一枚が、次の書き出しで消えることはありません。

## だから直したのは一箇所、そして「書けなかったとき」の話です

```
前: 電話が resolve すれば               →「書き出しました」
今: 電話が**ファイル名を返して初めて**  →「書き出しました」
    名前が無ければ                      →「ファイルの保存先に届いていません。」
```

**なぜ名前かというと、こちら側にある証拠がそれしかないからです。** Swift の
`sheet` は `try bytes.write(…)` に成功したときだけ `url.lastPathComponent` を
返し、他の道は全部 `reject` します。ブリッジ無し・reject・名前の無い answer は、
**人にとっては同じこと**（Files に無い）なので、同じ一文を出します。

**これが指示の ⚠ に当たるところです。** この章が人を傷つけられる唯一の道が
「書けていないのに書けたと言う」で、そのとき人は Files を開いて、何も無くて、
これから描くはずだった文字がどこにも行かない。

`shMake()` の上のコメントも直しました ──「There is no Swift behind `sheet`
yet」と書いてありましたが、sheet3 が入れたので**もう嘘**でした
（`CLAUDE.md`「a change lands with every sentence it falsifies」）。

## 「毎回」の読み方

**押すたびです。** プレビュー（`shPvDraw()`）は canvas に描くだけで、何も
書きません。もし「プレビューを作った時点でも」なら打鍵ごとに PDF が増える形に
なり、それは別物です ── そうは読んでいません。**リーダーに投げてあります。**

## 世代を回すか ── **回しません。リーダーが決めました（2026-08-27）**

**判断ではなく規則だ、というのがリーダーの答えです。** `CLAUDE.md`:

> Automatic deletion, pruning and cleanup are forbidden unless a written spec
> asks for them; anything that deletes gets a DELETE REVIEW first.

世代を回すのは**自動の削除**です。用紙は一枚一枚が別の紙で、Files で開いて
ペンで書いた一枚が「二枚目を書き出したら世代が回って消えた」は、人が書いた
ものが消えること。書かれた仕様が求めていない以上、**やらないのが既定**で、
やるなら DELETE REVIEW が先。**今の `<name> 2.pdf` のまま、何も変えていません。**

`keep()` が `.1` `.2` に回せるのは、バックアップが**置き換え**だからです ──
新しい方は古い方と同じことを後から言っているだけなので、三枚目が一枚目を
押し出しても誰の持ち物も減りません。**用紙は置き換えではありません。**

**その違いを `www/sheet.js` の書き出しのところにコメントで残しました**
（リーダーの指示）── 次に読む人が「バックアップは回しているのに、なぜこちらは
回さないのか」と思うところなので。
