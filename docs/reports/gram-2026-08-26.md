## ③ すでに選んでいる人の答えはどうなるのか ← **ここが一番大事**

**画面から六択を外すだけなら、値は残ります。** `STG.order` は誰も消しません。
`saveStg()` は `STG` を丸ごと書くので、読み手がいなくなっても文字列はそこにあり、
バックアップにも入り続けます。

**ただし、消える道が一本あります。そして、それは片付けとして自然に見える道です。**

`stRead()`（`phases.js:39-47`）は localStorage から STG を組み立て直すとき、
**キーを一つずつ名指しで写しています**:

```js
STG.done=stgs.done||{}; STG.notes=stgs.notes||{}; STG.set=stgs.set||{};
STG.extra=stgs.extra||[]; STG.rules=stgs.rules||{}; STG.ex=stgs.ex||{};
STG.fm=stgs.fm||[];
STG.order=stgs.order||''; STG.gpos=stgs.gpos||{};
```

丸ごとの `JSON.parse` を代入しているのではなく、**ホワイトリストです。** なので:

> 六択を画面から外したあと「もう `order` は読まれないから」と `stRead()` の
> `STG.order=stgs.order||''` の行を消すと、次の起動で `STG` に `order` が無くなり、
> **その次の `saveStg()`（メモを1つ書く、単語を1つ足す、どの決定を1つ触る、でも起きる）
> が `lingua.<id>.phases` を `order` 抜きで上書きします。**
> 保存されていた答えは、そこで恒久的に消えます。何も throw しません。画面は正しく
> 見えます。そのあとバックアップを取れば、消えた版がバックアップになります。

`docs/DATA_SAFETY.md`「人が作ったものは、今の形が要らないという理由で消さない」に
真正面から当たります。**どの案を採るにせよ、`stRead()` のその行は消してはいけません。**
`saveStg()` が `STG` を丸ごと書く以上、`stRead()` のホワイトリストが実質の「残す物の
リスト」になっています。ここは territory 内なので、私が守れます。

同じ理由で `orderDef()`（`grammar.js:34`）も残す必要があります — これが `STG.order` の
唯一の読み手で、下流は:

```
orderDef() → gModel() (grammar.js:130) → adapter.fromLegacy(..., {order:...})
           → model.wordOrder = ['SUBJECT','OBJECT','VERB']
           → translate.arrange() / morphology.parseSentence()
```

つまり**画面のボタンが消えても、保存された語順はエンジンが今日も使います。** 六択の
ボタンだけを外して `orderDef()` を残す形なら、既存ユーザーの答えは一バイトも動かず、
文の並びも今日と同じままです。これは③の答えとして重要です:
**「外す」は「消す」を含みません。含ませないことができます。**

もう一つ: `STG.set.order`（印）は `STG.set` ごと丸写しなので、印は残ります。ただし
`stTotal(p)=slots.length+feats.length+1` と `stFeatsDone()` が `feats:['order']` を
数えているので、`feats` から `'order'` を取ると**進捗の分母が変わります**。データは
消えませんが、その言語の「文法の進み具合」の表示は動きます。これは決定が要る副作用です。

## ④ `grammar-engine/` の新しい方は語順を何として持っているか

**六択と一対一です。** `model.js` の `wordOrder(value)` が `'SOV'` を
`['SUBJECT','OBJECT','VERB']` に開くだけで、`languageModel.wordOrder` はその配列です。
別の考え方（主要部の位置、格の有無）に置き換わってはいません。

**が、エンジンはすでに「語順ではない決め方」を持っています。** これが今回の話の核心です。

`morphology.js` に `CASE` があります（25行 `CASE_ROLE`、26行 `caseRole()`）:

- 単語が `feature:'CASE'` の inflection を持っていれば、**どこに立っていても**その役
  （SUBJECT/OBJECT/…）を取る
- 印のついた語が先に役を取り、その分は位置の待ち行列から**抜かれる**（110-113行）
- 印のない語だけが `model.wordOrder` の順で役を割り当てられる

そして助詞の書き方が二通り、両方読めます:
- くっつく `mi-ga` — ふつうの suffix
- **離れて立つ `mi ga`** — `operation:'suffix', separator:' '` の inflection
  （`morphology.js:92-96` のコメントがそう言っています）。前置助詞も対称に読めます（88行）。

つまりオーナーの言った「svoが基本でも助詞があるかもしれない」は、**エンジンの中では
すでに表現できる形になっています**: 語順は印のない語の落としどころで、助詞が印です。
`morphology.js` のコメントがそのまま「Word order is untouched and still decides every
word that carries no mark. Position OR mark, or both in one sentence -- not one
replacing the other.」と書いています。

**足りていないのは画面と保存です。** `www/` の中で inflection を作る場所は**一つも
ありません**（`grep inflections www/*.js` → `wordsheet.js` の語族表示だけで、これは
エンジンとは別物）。`gModel()` は `grammarRules` しか埋めず、`inflections` は常に空です。
`adapter.save()` / `load()` / `SLICES` の `'gram2'` は存在しますが、`grammar.js:90` が
「Nothing is written under `gram2`, and that is deliberate」と明言しています。
**エンジンは格を読めるが、この言語の格をどこにも書けない。**
