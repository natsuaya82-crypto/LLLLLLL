**ただし、消える道が一本あります。そして、それは片付けとして自然に見える道です。**

`stRead()`（`phases.js:39-47`）は localStorage から STG を組み立て直すとき、
**キーを一つずつ名指しで写しています**:

```js

STG.extra=stgs.extra||[]; STG.rules=stgs.rules||{}; STG.ex=stgs.ex||{};
```

丸ごとの `JSON.parse` を代入しているのではなく、**ホワイトリストです。** なので:

> 六択を画面から外したあと「もう `order` は読まれないから」と `stRead()` の
> `STG.order=stgs.order||''` の行を消すと、次の起動で `STG` に `order` が無くなり、

> が `lingua.<id>.phases` を `order` 抜きで上書きします。**
> 保存されていた答えは、そこで恒久的に消えます。何も throw しません。画面は正しく
> 見えます。そのあとバックアップを取れば、消えた版がバックアップになります。

`docs/DATA_SAFETY.md`「人が作ったものは、今の形が要らないという理由で消さない」に

`saveStg()` が `STG` を丸ごと書く以上、`stRead()` のホワイトリストが実質の「残す物の

## ④ `grammar-engine/` の新しい方は語順を何として持っているか

**六択と一対一です。** `model.js` の `wordOrder(value)` が `'SOV'` を

別の考え方（主要部の位置、格の有無）に置き換わってはいません。

**が、エンジンはすでに「語順ではない決め方」を持っています。** これが今回の話の核心です。

`morphology.js` に `CASE` があります（25行 `CASE_ROLE`、26行 `caseRole()`）:

- 単語が `feature:'CASE'` の inflection を持っていれば、**どこに立っていても**その役
  （SUBJECT/OBJECT/…）を取る
- 印のついた語が先に役を取り、その分は位置の待ち行列から**抜かれる**（110-113行）
- 印のない語だけが `model.wordOrder` の順で役を割り当てられる

そして助詞の書き方が二通り、両方読めます:
- くっつく `mi-ga` — ふつうの suffix

つまりオーナーの言った「svoが基本でも助詞があるかもしれない」は、**エンジンの中では
すでに表現できる形になっています**: 語順は印のない語の落としどころで、助詞が印です。
`morphology.js` のコメントがそのまま「Word order is untouched and still decides every

**足りていないのは画面と保存です。** `www/` の中で inflection を作る場所は**一つも

# §2 — 助詞が作れるようになりました

## 形は、この app が既に持っていたものです

**助詞は語です。** 否定の段が「ない」を作らせ、場所の段が「に」「から」を作らせるのと
同じ形。だから新しい画面の形も、新しい保存も、新しいルートも要りませんでした。

そして **`part`（助詞）の段は前から存在していました** —— `phases.js` の
`STAGES_IF` に、slots も feats も空で。コメントが既に今日の話と同じことを
書いています:

> Particles are the case that made the point: English has none, and a list that
> opens with a page for them is the app telling somebody their language has
> something it may well not.

**足りなかったのは二つだけです:** 枠（何を作らせるか）と、扉。

## 扉について —— ここだけ私が判断しました

`STAGES_IF` の段は `stUsed()` が真のときだけ一覧に出ます。`stUsed()` が見るのは
「触られた／メモ／規則／例文」で、**そのどれにも、新しい言語からは到達できません。**
`stAddOwn` は自分の段を作るもので、`part` には届きません。**段があって扉が無い。**

`CLAUDE.md` 規則19 がこれを名指しで書いています:

> **And that a page arrives with the way THERE and the way BACK already on it.**
> A face used to arrive as one empty key ... there was no way to it and no way
> off it — `docs/keyboard.md` described the trap in four steps, which is a
> manual page standing in for the thing working.

なので扉は要ると判断しました。**置いたのは一覧の「足」**で、自分で段を足すボタンの
隣です。頭に並べないこと（＝アプリがその言語に助詞が有ると言わないこと）と、
言いたい人が言えることは両立します。押すと段が一覧に入り、以後この扉は出ません。

**ここはオーナーのものかもしれません。** 扉が要ること自体は規則19が書いていますが、
**足に置いたのは私の判断**です。頭に出す・別の場所から入る・そもそも出さない、

# §14 第二章 ── 名詞。その語が実際にどう変わるか

`docs/GRAMMAR-V2-SPEC.md` §14 Nouns。旧の章は手つかず。

## できたもの

語順の下に **名詞** の節。**その言語自身の名詞**と、この言語がその語から作れる形:

```
複数形   tuf  ›  tufmi
主語     tuf  ›  tuf ga
```

エンジンに実際に作らせています。**規則を見せているのではなく、その語がそうなる**。

## 二つ目のエディタは作っていません

規則を書く場所は既に二つあり、どちらもこの章のものではありません:

| 規則 | 書く場所 | 行を押すと |
|---|---|---|
| 語形（複数・過去…） | 単語側の語形のページ | `openFmr` |
| 助詞（主語・目的語…） | 助詞の段 | `openSlot` |

**行はそのどちらかに戻ります。** どこから来た規則かは、エンジンの `metadata` に
乗せてあります —— `model.js` が保持して一度も読まない唯一のフィールドなので、
エンジンは「この app が何と呼んでいるか」を知らないままでいられます。

## 検査が一度、自分の穴で緑になり、そこから本物のバグが出ました

「何も変えない規則は行にしない」を、**別の feature の規則**で訊いていました。
章の絞り込みのほうで先に落ちるので、**どんなコードでも通る主張**です。

同じ feature の規則（複数形の作り方が二通りある言語）に直したら、**本物のバグが
出ました**:

> `g2Made()` が「この**規則**が何を作るか」ではなく「この**feature** で何ができるか」を
> 訊いていた。一つの feature は最初に当たった規則で使い切られるので、
> **同じ語が二つの違う名前の下に出ます。** どちらの行も正しく見えます。

模型をその一規則に絞って訊くようにしました。**これは私が今日エンジンに入れた
「一つの feature に一つの ending」の裏返しで、そこを直したから出てきたバグです。**

| 戻したバグ | 赤 |
|---|---|
| 何も変えない規則も行にする | 行が3つ（2つのはず）／変わらない行が1つ |
| 規則ではなく feature を訊く | 行が3つ |

# §14 第三章 ── 動詞

名詞の章と同じ形。**先に歩きを一箇所に出してから**（`g2Forms(pos, feats)`）、
動詞をその二人目の呼び手にしました。振る舞いを変えないコミットと、章を足す
コミットは分けてあります。

```
過去形   tir  ›  tirka
未来形   tir  ›  tirsu
受身形   tir  ›  etir      ← 前に付く規則が、前に出ている
```

「前／後ろ」のスイッチはアプリの語形エディタに前からありました。**それが作るものが
画面に出るのは初めてです。**

## 否定はここに出しません

`docs/GRAMMAR-V2-SPEC.md` §4 が章を分けていて、理由もそこにあります ——
「必ず PREFIX になると決めつけない」。否定は語尾でも語頭でも**別の単語**でも
表せるので、時制と並べて訊く話ではない。次の章です。

## 検査 ── 数えるだけにしていません

名詞の行も動詞の行も同じ class を着ています。**数えるだけの検査は、全部が一つの
見出しの下に出ていても通ります。** どの見出しの下にあるかをページから読みました。

赤を見た二件:

| 戻したバグ | 赤 |

| 前置を後ろに付ける | `etir` が出ない |
