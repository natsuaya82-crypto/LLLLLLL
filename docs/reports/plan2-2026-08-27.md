## 0. オーナーへ ── 「800円と8000円では？」

**そのとおりです。あの ¥750 と ¥6,000 は偽物で、検査用の作り物でした。**

`tools/plan-check.mjs` が偽の App Store を立てるところの数字で、**わざと本当の値段
にしていません。**理由はその検査自身が書いています ── 割引が **33** になるように
選んである、**17 が出てしまうと、その 17 がどこから来た数字なのか何も証明できない**
から。`PLANS` にも `off:'17'` と書いてあるので、17 が画面に出ているだけでは
「計算した 17」なのか「書いてあった 17 をそのまま出しただけ」なのか区別が
つきません。

**本当の値段（¥800 / ¥8,000）を通したらどうなるか、実際に動かしました:**

```
月         ¥800  / month
年  ¥9,600 ¥8,000 / year        ← ¥9,600 に取り消し線
                    17% off
```

- 取り消し線の **¥9,600** は 800 × 12 で、**App Store 自身に整形させた文字列**です。
- **17% off** は ¥800 と ¥8,000 から計算した数字です
  (`1 - 8000/(800*12) = 16.67% → 17`)。`PLANS` に書いてある 17 ではありません。
  ドルの $4.99 / $49.99 でも 17 になります。
- **アプリは値段を一つも持っていません。**App Store Connect に登録した値段が
  `displayPrice` として降りてきて、それをそのまま出します。国が変われば
  その国の通貨と書式で出ます。

**検査の数字は偽物のままにします。**本当の値段を検査に書くと 17 が出てしまい、
上のとおり何も証明しなくなります。それと、値段が変われば検査の中の数字が
古くなります ── 値段は App Store のもので、repo のものではありません。

## 1. 入っているもの (`dd242e8`)

```
49.99は取り消し線＋17%OFF
4はドル。でもさっき価格登録してきたけど日本円は800円とかになってたよ  OWNER 2026-08-26
```

**足りなかったのは元値だけでした。**割引率は前から金額から計算されています。

| ファイル | 何を |
|---|---|
| `ios/App/App/LinguaStore.swift` | `row["year"] = (p.price * 12).formatted(p.priceFormatStyle)` |
| `www/store.js` | `storeWas(planId)` ── 月額の行の `year` を読むだけ |
| `www/settings.js` | `planPrice()` が年額の側にだけ `<s class="pwas">` |
| `tools/plan-check.mjs` | 主張を七つ |

**なぜ Swift でやるか。** `www` に来ていたのは `price`（整形済みの文字列）と
`amount`（数だけ。通貨コードも locale も無し）で、`amount*12` をこちらで整形すると
円で課金される人に `$9600` を見せることになります。`LinguaStore.swift` 自身の
コメントが先に書いていました ──「Building "$" + a number is how an app ends up
showing dollars to somebody being charged yen」。

**App Store が答えないときは何も出しません**（ブラウザ、スクリーンショット、
まだ作っていない商品）。`www/i18n` に `$59.88` を置く道はリーダー経由でオーナーが
断りました ── 取り消し線は隣の数と比べられるためだけに在るので、そこにドル記号を
出すのは「違う数」ではなく「嘘」です。`year` が来ても**割引が無ければ**線は
引きません（年額の商品が無い Pro がその形）。

### 赤を四つ見ました

| 戻したバグ | 赤くなった主張 |
|---|---|
| `amount*12` を `www` で組み立てる | `$9000` が出て**三つ** |
| `storeOff()` の門を外す | 年額の無い Pro が線を引く |
| 月の側にも出す | 月が自分の12倍で消される |
| `$59.88` を fallback にする | **二つ**（App Store が答える前／`year` 抜きで答えたとき） |

## 2. リーダーに入れてほしい CSS ── **⑪ の不具合の修正を含みます**

`www/index.html` はこの枝のものではないので、そのまま貼れる形で置きます。

### 先に、⑪ が今 master で壊しているもの

**⑪ の `.plterm .pp{display:inline}` は、320pt で値段を数字の途中で割ります。**
取り消し線とは無関係で、Pro の段（取り消し線なし）でも起きます:

```
$99.9        ← 320pt、iPhone SE 初代。数字が行をまたいで割れている
9 / year
17% off
```

そして **390pt でも「一列」になっていません** ── `$9.99` 112px ＋ `/ month`
50px ＋ `margin-left` 3px = **115px** に対し、`padding:10px 12px` を引いた中身の
幅が **112px**。3px 足りずに折り返します。オーナーが言った
「4.99/月は一列にしろ」は、今の master では**満たされていません。**

`press` は 402pt でしか測らないので、どちらも検査には出ません。

### 入れてほしいもの ── `.plterm .plsave{…}`（1459行）の後ろ、または `.btn.plterm` の隣

```css
/* 1.25rem was 3px too wide for `$4.99 / month` to sit on one line inside the
   box ⑪ put round it, so 「4.99/月は一列にしろ」OWNER 2026-08-26 was not
   actually met -- and at 320 the amount broke mid-number (`$99.9` / `9`).
   Measured at 320 and 390, both currencies, both terms. */
.btn.plterm{padding:10px 8px}
.plterm .pp{font-size:1.1rem}
/* An amount never breaks, and neither does its term: what may drop to a
   second line is the whole of `/ month`, and only on a 320 phone. */
.plterm .pp,.plterm .pper{white-space:nowrap}
/* Twelve months at the monthly price, struck through, on the line above what
   a year costs. Its own line: beside the price it pushes the amount into a
   second line, which is the thing above. Muted and small -- it is the number
   being compared AGAINST, and the one being paid is the big one.
   「49.99は取り消し線＋17%OFF」OWNER 2026-08-26. */
.plterm .pwas{display:block;font-size:.72rem;color:var(--txm);line-height:1.35;
              white-space:nowrap}
```

**`tools/box-baseline.txt` は動きません** ── `border` も `border-radius` も
足していません。

### 測った結果（`have` は中身の幅、`need` は 値段＋単位＋margin）

| | need / have | 一列 | need / have | 一列 |
| `¥800 / month` | 98 / 112 | ✓ | 98 / 84 | 単位が2行目 |

### 一緒に入れてほしい fixture の面

CSS を入れると `.pwas` は「index.html が飾っているのに誰も着ていないクラス」に
なります ── `press` の walk はブラウザで走り、ブラウザに App Store は無いので
`storeWas()` は常に空です。`tools/css-baseline.txt` に一行足すより、
その頭が書いているとおり**種を足すほうが良い**ので:

```js
    /* The plans page after the App Store has answered. Every other walk runs
       in a browser, where there is no App Store at all, so the struck-through
       price a year carries is on no screen any of them reaches -- and a class
       nothing wears reads as a class nothing needs.
       「49.99は取り消し線＋17%OFF」OWNER 2026-08-26. The numbers are the same
       fakes tools/plan-check.mjs uses and for the same reason: a saving that
       comes out 33 cannot be the 17 written on PLANS. */
    ['the plans, priced by the App Store', () => {
        STORE_P = { 'com.tokinets.lingua.plus.monthly':
                      { price: '¥750', amount: 750, year: '¥9,000' },
                    'com.tokinets.lingua.plus.yearly':
                      { price: '¥6,000', amount: 6000 } };
        const h = vPlans(); STORE_P = null; return h; }],
```

`window.Capacitor` は要りません（`vPlans()` の `storeAsk()` はブラウザでは
何もしないので、`STORE_P` はそのまま残ります）。**確かめてあります。**
`screens walked` が +1、`buttons pressed` はプランの段一枚ぶん増えます。
