# A. 上のボタンは、何が選ばれているときに何を出すか

**左が今、右が案。決まっていないところは「？」と書いてあります。**

## **決めてもらわないと進めないのは、ここ一つです**

**結合の行き先。** 今は「キーを選んで、隣のキーをタップすると結合」で、
**タップから外すと結合する道が無くなります。**

`kbJoin()`（横）と `kbVJoin()`（縦）は、**タップ以外から呼ばれていません**
（横は上の「結合」ボタンからも呼べますが、縦はタップだけです）。道が消えると
`dead-check` が「何も呼んでいない関数」で赤になるので、**外すのと同時に行き先が
要ります。**

三つの形が考えられます:

| | どうなるか | 代償 |
|---|---|---|
| **A 2キー選択中に「結合」** （リーダーの案） | 二つ選んで押す。横に並んでいれば横結合、縦なら縦結合 | 選ぶ→押す の二手。今は一手（隣をタップ） |
| **B 1キー選択中に「右と結合」「下と結合」の二つ** | 今の「結合」ボタンの隣にもう一つ | ボタンが一つ増える。1キー選択時は編集と合わせて三つ |
| **C 1キー選択中に「結合」一つ、押すとどちらか訊く** | ＋ が「上／下」を訊くのと同じ形 | 一手増える。ただし ＋ と同じ習わしなので画面の中では一貫する |

**私は A が素直だと思いますが、決めるのはオーナーです。**
「複数キー選べる」ようにするのがそもそもの決定なので、
**選んでから押す、という形に他のボタンも全部揃っている**からです。

**この答えが来るまで、①（結合をタップから外す）には手を付けません** ──
外した瞬間に道が消えるので、外すことと行き先は一つの変更です。

# B. 一枚目の盤で押しても何も起きない件 ── 実測

**「押しても無反応」ではありませんでした。押せるものが一つもありません。**

`kbAdd('qwerty')` で自分の盤を一枚作り、`kbShow` を 0（無料 QWERTY）と
1（自分の盤）にして、同じ画面を二回描いて数えました:

| | board 0（無料QWERTY） | board 1（自分の盤） |
|---|---|---|
| `kbIsFree()` | true | false |
| `kbEdit()` | **null** | 盤を返す |
| 描かれるキー | **43枚** | 43枚 |
| そのうち押せる（`[data-do]` を持つ） | **0枚** | **43枚** |
| 上のボタン（`.kbtool .kbtb`） | **0個** | あり |
| 行番号（`.kbrn`） | **0個** | あり |
| 列記号（`.kbhdr .kbcl`） | **0個** | あり |

**タップは飲み込まれているのではありません。** キーが `<button>` ですらなく、
`KBH` は触られもしません（押す前と後で `#app` の中身が 1 バイトも変わりません）。

**そして、行番号も列記号も上のボタンも、一つも出ていません。** つまりこの画面は
「反応しないシート」ではなく、**シートではありません** ── キーボードの絵です。

**これが「押しても選ばれない」の正体だと思います。** 二枚の盤は**同じ43枚の
キーを同じ形で**描くので、タブを切り替えても絵はほとんど変わりません。片方は
シートで、片方は絵で、**見分けるものが画面に何もありません。**

**手は付けていません**（リーダーの指示どおり）。設計としては正しい ── board 0 は
無料の QWERTY そのもので、編集できないことがその盤の意味です。**ただ、触った人に
壊れて見える理由は、上の数字がそのまま説明しています。**

**アプリ内に説明を書くのは禁止**なので、直すなら「編集できないことが**見て**
分かる」形になります。それは見た目の判断なので、オーナーのものです。
