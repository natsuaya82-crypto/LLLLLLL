## 何をしたか

長押しで `.lift` が付くのも、指について動くのも、当たり判定から外れるのも、
**掴んだ一つだけ**でした。残りは平らなまま元の場所に留まり、指を離した瞬間に
飛びます。オーナーの手本は iPhone のホーム画面で、そこでは選んだものが全部
ついて来ます。

| file | 何を、なぜ |
|---|---|
| `www/keyboard.js` | `kbCarried()` `kbCarryAt()` `kbCarryHit()` `kbRunEls()` を足し、`kbDown` `kbLift` `kbDragTo` `kbUp` がそれを通る。**四つは同じ集合に対する四つの動作なので、集合を一箇所で言います** ── 別々だったから「持ち上げは一つ、着地は全部」にずれていました |
| `tools/kb-check.mjs` | `dragWatch()` と主張三本。運びの**途中**（アプリが「指の下は何か」を訊く瞬間）を測ります |
| `docs/CHANGELOG.md` | 記録 |

## 自分で入れかけた回帰を、主張で押さえました

持ち上がったキーは**指の真下**に居るので、`elementFromPoint` が自分を答えます。
掴んだ一つだけを外していて足りていたのは、動くのが一つだけだったからです。
**n 個持ち上げて一つしか外さないと、二個目が答えて運びが黙って断られます** ──
何も起きず、何のしるしも出ません。だから主張を一本立てました。

### 四本目は書いて、消しました

「指を離したら全部下りる」は、**`kbUp()` の後始末を消しても緑のままでした。**

`kbUp()` は `kbReadRows()` を呼び、その終わりが `render()` で、**盤ごと作り直され
ます。** 測りました ── 運んだ 3 個のうち、離した後も画面に残っている element は
**0 個**。だから「持ち上がったまま残ったキー」は後始末があってもなくても見つからず、
主張が何も押さえていません。

**赤にならない緑は、無いより悪い**（信じられるので）。消して、**なぜ書かないか**を
検査の中にコメントで残しました ── 次に読む人が「これが抜けている」と思って足し
戻さないように。後始末そのものは残してあります（元からある正しい動作で、消す理由が
ありません）。
