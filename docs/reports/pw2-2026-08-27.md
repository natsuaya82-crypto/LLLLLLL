### 1. `.view.fit .pwscroll` / `.pwqs` / `.pwtop` (1015-1017 行あたり)

**今:**
```css
.view.fit .pwscroll{flex:1;min-width:0;min-height:44px;overflow:auto}
.view.fit .pwqs + .pwscroll{min-height:88px}
.view.fit .pwtop{min-height:0}
```

**こう:**
```css
.view.fit .pwscroll{flex:1;min-width:0;min-height:162px;overflow:auto;
   display:flex;flex-direction:column}
.view.fit .pwqs{flex:0 1 auto;min-height:44px}
.view.fit .pwtop{flex:1 1 auto;min-height:0}
```

`.pwqs + .pwscroll` の行は**消えます**。88 と 44 が二つの数字だったのが
一つになるからで、そこが要点です ── 「書く箱は二つの欄」は返信かどうかで
変わらない一つの事実で、44 と 88 は同じ事実を二回、違う数で言っていた。

162 の内訳は測った数です: 行 44 + `.pwgl` 6 + 意味 (10+44) + `.pwtop` の
下 6 + 列の床との差。空の作文画面の実測 content が横 110 / 縦 162。

`display:flex` は下の 2 と一組です。これが無いと `.pwtop` に確定した高さが
無く、列は自分が何の中に居るのか訊けません。

### 2. `.view.fit .pwfield .lnin.dir-ttb-*` (1026-1029 行あたり)

**今:**
```css
.view.fit .pwfield .lnin.dir-ttb-rl,
.view.fit .pwfield .lnin.dir-ttb-lr{
   height:calc(var(--vvmin,55vh) - 230px);min-height:150px;
   max-width:100%;overflow:auto}
```

**こう:**
```css
.view.fit .pwfield .lnin.dir-ttb-rl,
.view.fit .pwfield .lnin.dir-ttb-lr{
   height:auto;flex:1 1 auto;min-height:96px;
   max-width:100%;overflow:auto}
```

**`230` が壊れていた数です。** 返信でない作文画面で測られた数で、そこでは
`.pwscroll` が 70 から始まる。返信では 242 から始まる（vvmin 508）。列は
`vvmin - 230` を要求し、箱は `vvmin - 300` しか無いので、意味は差のぶん
だけ押し出される ── **その差は画面が大きいほど開く。**

`96` は列が列として読める床（4文字ぶん）。ここが 44 だと列が潰れて、横倒し
の逆順みたいに見えます（絵で確認した）。

`.pwstrip` を `flex:0 0 auto` にする案も測りましたが、**数字が一つも動かな
かった**ので入れていません。

## 2-1. 返信の作文画面で、意味の欄が見えない — CODE CONFIRMED（CSS 待ち）

> 「自分の言語で一行と意味がこのページで見れるように。」

### 測り直した結果、リーダーの数字は再現しませんでした

リーダーの実測（`.pwscroll` 211..446 / `#pw-mn` 284..328、両方入っている）は
**`--vvmin` が 508 のときの数字**です。508 は 390x844 にキーボード 336 が
出た状態 ── つまり**一番広い場合**を一度だけ測って「入っている」と読んだ。

`post-check` の 11d は `--vvmin: 300` で測っていて、そこでは入っていません。
同じ画面について二つの測定が食い違っていたのではなく、**別の大きさを測って
いた**。

### 条件は四つあり、一番大きいのは「向き」です

`#pw-mn` の底が `.pwscroll` の底からどれだけ出るか（0 = 入っている）:

| 見えている高さ | 横 新規 | 横 返信 | 縦 新規 | 縦 返信 |
|---|---|---|---|---|
| 260 | 0 | **29** | **88** | **128** |
| 300 | 0 | **29** | **48** | **128** |
| 380 | 0 | **9** | 0 | **108** |
| 420 | 0 | 0 | 0 | **118** |
| 508 | 0 | 0 | 0 | **109** |
| 560 | 0 | 0 | 0 | **153** |

**縦書きは、どの大きさでも外に出ます。そして画面が大きいほど酷くなります。**
ここの他のどの規則とも逆向きで、一台の電話・一つの言語で試している限り
絶対に見えません。オーナーは自分の言語で書いているので、これが実機の症状の
はずです。写真の有無は数字を動かしません（帯は意味の**下**にあるので）。

縦書きは `can('dir')` = `pro` なので、**無料と plus では到達できない**分岐
です。歩き回る検査が free で走るので、誰も一度も見ていなかった。
