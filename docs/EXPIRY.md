## 1. キーボードを一度も作っていない言語は、バックアップファイルが書かれなくなる

**何が、どういうときに消えるか。**
その言語のバックアップファイル（iPhone の中の `Documents/Languages/`）が、
**それ以降ずっと書かれなくなります。** 単語も文字も、後から足したものは
ファイルに一度も入りません。サーバーとこの iPhone の両方が駄目になった日に
残っているのは、止まった時点の古いファイルだけです。

起きるのは、キーボードを一度も組んでいない言語から**離れたとき**です ──
言語を切り替える、言語を消す、アカウントを消す。

**どこにあるか。**

| | |
|---|---|
| `www/keyboard.js:137` | `saveKb()` が `JSON.stringify(KB)` を書く。KB が空のときは文字列 `"null"` になる |
| `www/keyboard.js:44` / `:83` | キーボードを組んでいない言語では `KB` は空（`kbRead()`） |
| `www/core.js:185` `:530` | 言語を切り替えると `langSaveAll()` → `saveKb()` |
| `www/settings.js:519` `:684` | 言語を消したとき・アカウントを消したときも同じ |
| `www/keyboard.js:3634` | `kbResetGo()`（キーボードを初期状態に戻す）も同じ状態を作る |
| `www/backup.js:82` | `bkSound('kb', 'null')` は「壊れている」と答える |
| `www/backup.js:183` | だから `bkPush()` が「書かない」で止まる |

**それは人が作ったものか。** はい。言語まるごとです。

**書いた仕様はあるか。** ありません。
`docs/DATA_SAFETY.md` は逆のことを言っています ──
「A wipe, a switch and a brand new language all produce an empty slice and all
of them are written」。空の言語は書かれるはずのものです。
`tools/backup-check.mjs:434` の「空の言語」の場面は、スライスのキーを**消して**
から試すので、アプリが実際に書く `"null"` という形は試されていません。

**確かめたこと。** `www/backup.js` の `BK_SHAPE` `bkSound()` `bkOK()` を
そのまま取り出して走らせ、`bkSound('kb','null')` が `false`、
kb に `"null"` が入った荷物で `bkOK()` が `false` になることを確認しました。
残りはコードを読んだだけです。**実機では押していません。**

**直す大きさ:** 小。空のキーボードを `"null"` ではなく空の物として書くか、
`bkSound()` が `null` を「無い」として扱うかの、どちらか一行です。
**どちらにするかはこのセッションが決めることではありません。**

## 9. サーバー側 ── 自動で消えるものは無い
