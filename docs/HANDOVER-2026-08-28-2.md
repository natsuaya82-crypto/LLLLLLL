### 1. Google のサインイン

**オーナーの原文**:

```
passed nonce and noce in id_token shoud either both exist or notって出るけど？ログインしようとすると
```
```
google
アップルはログインできた。
```

**Apple は通る。Google だけ通らない。**エラー文は Supabase（GoTrue）のもので、
`id_token` の中の nonce と、こちらが渡した nonce が**片方だけ在る**ときに出る。

測った事実:

- ビルドは `npm ci`（`.github/workflows/ios-deploy.yml:32`）なので、入っている
  のは**ロック通りの `@capgo/capacitor-social-login` 8.4.4**。最新の 8.5.0 ではない
- **8.4.4 は、こちらが渡さなければ nonce を作らない** ──
  `GoogleProvider.swift:52-59` が `payload["nonce"]` を読んで
  `GIDSignIn.signIn(..., nonce: nonce)` に渡すだけ。`AppleProvider.swift:213` も同じ
- アプリ側も送っていない ── `www/onboard.js` の `obSocial()` が
  `netIdToken(who, tok, '', ...)` を呼び、`www/net.js:442` が
  `if(nonce) b.nonce=nonce;` なので空文字は送られない
- `www/onboard.js:687` に「nonce は要らない」という長いコメントがある。
  **Apple については正しく、Google については間違っている**ことになる

**つまり「両方無い」はずなのに Supabase が食い違いを言っている。そこが未解決。**
次にやるなら、送っている `id_token` を割って（base64 の真ん中）**nonce クレームが
実際に入っているか**を見るのが早い。

**直し方は Apple と Google で違う。逆にすると通らない**:
- **Google**: `GIDSignIn` に渡した nonce が**そのまま** `id_token` に入る →
  **同じ文字列**をプラグインと Supabase の両方へ
- **Apple**: リクエストには**SHA-256 のハッシュ**、Supabase には**生の文字列**

**Apple はいま通っている。壊さないこと。**

### 2. `⋯` が画面に出ない

道は `⋯`（`kbMoreQ()` → `kbMore()`）→「配置を変える」（`kbRepat()`）→
型を選ぶ（`kbSetPat()`）→ 確認。**一段目が画面に無い。**

有料プランで盤を一つ作った状態で測った:

```
                       here().a   kbShow   [data-do="kbMore"] が画面にあるか
kbAdd の直後（引数なし）  undefined     1        ない
go('kb','1') のあと        "1"        1        ない
```

**`kbMoreQ()` は文字列としてボタンを返している** ──
`<button class="navq" data-do="kbMore" …>`。**返っているのに DOM に無い。**
`vKb()` は三箇所で `navTop('', kbMoreQ())` を呼んでいる
（`www/keyboard.js` の 2085 / 2095 / 2100 付近）。**`navTop()` の第二引数が
落ちているか、`vKb()` 以外が描かれているかのどちらか。**`www/shell.js` の
`navTop()` を読むこと。

**幅の計算は壊れていない。**`kbSetPat('flick')` を直接呼ぶと `1×10 → 2.5×4` に
変わり、端末へ送る値も 2.5 だった。**壊れているのは道だけ。**

**そしてこれは検査の穴でもある。**`kbMore` `kbRepat` `kbSetPat` は三つとも
`act-map.js` に登録され関数も在るので `dead` も `act` も緑。それを見るのは
`press` だが、`press` は `tools/fixture.mjs` の顔を歩き、**顔の側では `⋯` が
出ている**（`shots/half-a-key-of-the-keyboard-selected.png` に写っている）。
**fixture と、実際に歩いて着く状態が食い違っている。そこも塞ぐこと。**
